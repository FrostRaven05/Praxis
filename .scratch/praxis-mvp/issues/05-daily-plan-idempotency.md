# 05 — 把同一任务安排到某日且双端去重

**What to build:** 用户从任务详情将已有任务加入指定日期，连点或两端同时操作都只产生一条安排。

**Blocked by:** 04 — 保留并解决两端任务编辑冲突。

**Status:** ready-for-agent

**Milestone:** M0

**依据:** 技术路线 §4、§5.2；Spec §5.2、§8.1(3)。

- [ ] 可选择执行日期并加入今日；不复制 Task，执行日期独立于任务截止时间。
- [ ] 本地和云端按用户、任务、日期约束活跃每日安排唯一；重复接受返回规范安排 ID。
- [ ] 本地临时 ID 收敛到规范 ID 后，重写后续待同步引用，保留历史与操作结果。
- [ ] 两端同时设置不同安排属性时保留冲突，不以去重为由丢弃输入；基础安排属性冲突复用同步协议。
- [ ] 测试连续点击、并发创建、响应丢失和离线重启；M0 从详情安排，正式建议入口由后续 Ticket 接入。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
