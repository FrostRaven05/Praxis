# 22 — 记录跨日部分推进和实际投入

**What to build:** 用户每天记录同一任务的推进说明，最后完成时项目只计算一次完成。

**Blocked by:** 11 — 按日浏览已安排任务和执行事实；13 — 用子任务拆解工作并正确汇总父任务；18 — 通过看板推进、阻塞和取消任务。

**Status:** ready-for-agent

**Milestone:** M3

**依据:** Spec §5.3、§6.6–6.7、§8.1(8)；技术路线 §4。

- [ ] 任务详情可新增当日部分推进、说明及可选耗时，未记录耗时为 null。
- [ ] 部分推进不自动完成任务，完成仍复用最终完成命令；执行记录关联原任务与用户日期。
- [ ] 今日、日历和项目进度可回看推进，叶子任务完成数与推进记录数明确区分。
- [ ] 用户可修正误录事实，通过历史/补偿保留原记录；同步冲突不覆盖说明。
- [ ] 测试跨三天推进后完成、父子统计、重复上传及没有记录时长的展示。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
