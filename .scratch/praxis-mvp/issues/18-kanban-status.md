# 18 — 通过看板推进、阻塞和取消任务

**What to build:** 用户从看板切换任务状态，所有现有视图显示同一结果，并能查看阻塞原因。

**Blocked by:** 07 — 完成任务并撤销误完成；12 — 创建项目并拆出可执行任务。

**Status:** ready-for-agent

**Milestone:** M2

**依据:** Spec §5.1、§6.1、§6.5；技术路线 §3、§4。

- [ ] 待办、进行中、阻塞、完成四列；桌面拖拽，移动菜单切换，完成复用原子完成命令。
- [ ] 开始/阻塞只改状态和原因，不改变日期；今日显示阻塞任务及原因，禁止作为立即可执行候选。
- [ ] 取消任务默认不在主列，任务列表可筛选；取消支持历史与带版本撤销。
- [ ] 所有新状态支持离线、同步和冲突；看板不持有第二份独立任务数据。
- [ ] 测试新任务进入待办、完成联动、取消后恢复及状态与完成事实一致。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
