# 08 — 断线及崩溃后继续同步未提交操作

**What to build:** 用户经历断网、应用崩溃或长期离线后，仍能恢复未完成同步并看到可处理的错误。

**Blocked by:** 06 — 改期、处理并发改期并支持撤销；07 — 完成任务并撤销误完成。

**Status:** ready-for-agent

**Milestone:** M0

**依据:** 技术路线 §5、§8 M0；Spec §8.1(11)、§9。

- [ ] 有界批次、指数退避与按设备因果顺序确认；本地连续改期/完成的基版本能随确认结果衔接。
- [ ] 拉取中继续编辑时，落地远端变更后重放待确认操作，不覆盖本地输入；重放冲突可见。
- [ ] 演练上传成功响应丢失、提交中断、乱序重复请求和游标写入失败，最终结果一致。
- [ ] 全量快照恢复先保护 outbox，再取一致快照及游标并重放；首版不自动清理历史和 tombstone。
- [ ] 展示拒绝、冲突、认证失效、协议不兼容等可行动状态；失败不静默丢命令。
- [ ] 以测试夹具验证删除/tombstone 与离线编辑不能自动复活记录，不新增超出 Spec 的用户删除界面。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
