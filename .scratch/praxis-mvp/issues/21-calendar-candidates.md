# 21 — 在日历查看未来候选并主动安排

**What to build:** 用户按日期浏览项目计划候选，明确区分建议、已安排和已发生的执行事实。

**Blocked by:** 11 — 按日浏览已安排任务和执行事实；20 — 接受、忽略或改日处理今日建议。

**Status:** ready-for-agent

**Milestone:** M2

**依据:** Spec §6.4、§8.1(5,6)；技术路线 §6。

- [ ] 未来日按目标日期调用共享规则，依赖状态依据当前已知事实，不假设届时必然完成。
- [ ] 跨日甘特任务可在多日候选区出现，始终关联同一任务，未接受不算每日工作量。
- [ ] 可将候选加入该日，复用接受与去重；未来任务主动提前必须确认。
- [ ] 历史日只显示当时安排与执行记录，不用当前计划重新生成候选。
- [ ] 验证未来添加、跨多日候选、已安排过滤、排期变化和历史不变。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
