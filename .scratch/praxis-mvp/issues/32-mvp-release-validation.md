# 32 — 用可安装版本完成首版端到端验收

**What to build:** 用户安装候选版本后完整跑通项目拆解、今日执行、总结与周报闭环，团队获得可复现的发行验收证据。

**Blocked by:** 17 — 预览受影响排期并确认或撤销调整；24 — 处理昨日及总结中的遗留事项；27 — 设置任务、晚间总结和周报提醒；28 — 导出完整项目数据及回顾历史；29 — 提供同一账号的 Web 在线补充入口；30 — 安装升级后保留离线数据并继续工作；31 — 在独立部署环境使用并恢复账号数据。

**Status:** ready-for-agent

**Milestone:** M3

**依据:** Spec §8.1 全部；技术路线 §8。

- [ ] 逐项执行 Spec 首版 12 条场景，包含三视图同源、建议去重、依赖、历史、部分推进和异常提示。
- [ ] 至少一台桌面与一台移动设备完成离线、重启、重连及冲突闭环；任何核心失败均阻止发行通过。
- [ ] 验证安装包通知、文件导出、账号切换、升级与服务恢复；记录目标平台矩阵，不以 Playwright 结果代替真机。
- [ ] 以一万历史任务、单项目五百任务和一千待同步操作测量查询、滚动与同步，记录设备、延迟和失败率；不虚构已达成的性能指标。
- [ ] 归档测试步骤、版本、结果及剩余缺陷；只处理阻止这些已实现流程通过的整合问题，大幅新增需求另开 Ticket。
- [ ] 确认甘特、看板和周报均在首版；AI、智能重排、重复任务、小组件及复杂时间块保持后续范围。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
