# 25 — 基于事实生成、编辑和导出周报

**What to build:** 用户无需每天写总结，也能生成按项目汇总的周报，编辑下周重点并保存及导出。

**Blocked by:** 09 — 在安装端验证任务提醒与文件导出；21 — 在日历查看未来候选并主动安排；23 — 生成并保存带快照的晚间总结。

**Status:** draft — awaiting breakdown approval

**Milestone:** M3

**依据:** Spec §6.7、§8.1(10)；技术路线 §4、§6。

- [ ] 按用户时区周一至周日汇总原计划、完成、临时新增、重点推进、项目变化、遗留和阻塞。
- [ ] 读取执行事实、项目事件和已有总结；没有总结的日期仍计入，部分推进另列，完成按唯一叶子任务去重。
- [ ] 成果可回溯到任务或记录，未知耗时显示未记录，计划不写成已完成。
- [ ] 汇总下周排期候选及重点；用户确认后才调用安排或排期命令，不自动发送周报。
- [ ] 双端编辑保存独立版本并同步，离线可生成；导出 Markdown，桌面保存/移动分享复用原生适配。
- [ ] 覆盖周边界、跨日任务、无总结、无 AI、事实撤销和来源链接。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
