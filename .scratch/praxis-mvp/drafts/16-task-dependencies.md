# 16 — 编辑前置依赖并阻止并发成环

**What to build:** 用户在任务详情及甘特中维护前置关系，能看到依赖连线并获得无效依赖提示。

**Blocked by:** 13 — 用子任务拆解工作并正确汇总父任务；15 — 在甘特图查看和编辑日粒度排期。

**Status:** draft — awaiting breakdown approval

**Milestone:** M2

**依据:** Spec §6.2、§6.5、§8.1(7)；技术路线 §5.2、§6。

- [ ] 首版只支持前置完成后开始；双端可添加/移除依赖，甘特绘制连线。
- [ ] 前后任务组合唯一，禁止自身、跨项目及循环依赖；汇总父项不可造成父子执行重复。
- [ ] 服务端在项目锁内读取最新依赖图后提交；两端各自合法但合并成环时拒绝后一操作。
- [ ] 依赖变更更新相关计划版本并同步，已安排任务保留，潜在阻塞明确提示。
- [ ] 验证链、分叉、并行任务、离线并发成环与跨用户引用；依赖不自动代表任务已完成。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
