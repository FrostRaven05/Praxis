# 23 — 生成并保存带快照的晚间总结

**What to build:** 用户从今日页生成结构化晚间总结，离线补充笔记和明日关注后保存。

**Blocked by:** 10 — 今日重点、负载与收件箱录入；22 — 记录跨日部分推进和实际投入。

**Status:** draft — awaiting breakdown approval

**Milestone:** M3

**依据:** Spec §6.6、§8.1(9)；技术路线 §4、§5.3、§6。

- [ ] 草稿包含按项目完成、重点完成/部分推进/未推进、临时新增影响、遗留与阻塞。
- [ ] 区分原计划和当天临时新增，使用安排历史及执行事件，不依赖当前任务状态猜测过去。
- [ ] 保存不可变版本、执行/计划快照、源事件引用与用户笔记；两端编辑同日总结保留版本与冲突。
- [ ] 允许尚未处理遗留时保存；离线保存后重启存在并能同步。
- [ ] 测试没有完成项、没有耗时、跨日任务及保存后改期不改写旧总结。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
