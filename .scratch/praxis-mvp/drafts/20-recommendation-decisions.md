# 20 — 接受、忽略或改日处理今日建议

**What to build:** 用户把建议加入今日或设为重点，也可今日忽略或明确改到未来日期。

**Blocked by:** 06 — 改期、处理并发改期并支持撤销；19 — 按计划和依赖生成可解释的今日建议。

**Status:** draft — awaiting breakdown approval

**Milestone:** M2

**依据:** Spec §6.2、§8.1(3,6)；技术路线 §4、§5。

- [ ] 接受复用安排去重命令，从建议区移除并出现在今日和日历；设为重点复用每日属性。
- [ ] 两端接受只保留一条安排；安排属性不一致时进入已有冲突流程。
- [ ] 忽略按任务和日期保存，当天排期版本变化也不重复出现；次日按最新计划判断。
- [ ] 改日生成明确未来安排并留事件，不自动提前；服务端验证计划版本和当前执行资格。
- [ ] 离线接受后联网发现资格变化时保留操作结果并提示处理，不悄悄丢失或当作正常接受。
- [ ] 测试连点、双端接受、忽略后重算、前置撤销完成和项目暂停时接受。

**完成边界:** 交付本行为所需的数据约束、应用用例、存储/同步或 API、可操作界面及验证证据；已有能力复用。安装端新增业务行为须验证离线持久化、重连收敛和失败提示。纯本地原型阶段不虚构已接通云端；API 从登录同步切片起持续覆盖。后续功能不塞入本 Ticket。

**演示证据:** 提供本 Ticket 的用户操作步骤、验证命令或设备记录、实际结果和未验证环境；不得把计划中的测试勾为已完成。
