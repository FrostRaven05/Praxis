## 数据变化与恢复路径

新增 0010 迁移：原始收集、记录、记录链接、澄清输出、内容事件、项目上下文；任务新增来源和软删除字段。扩展 outbox 接受新领域命令。原文、所有输出、来源、事件及 outbox 在同一事务提交。

升级现有数据库前，使用 SQLite VACUUM INTO 创建包含已提交 WAL 的一致性备份，位于当前数据库旁的 `backups` 目录。备份失败即停止迁移。旧任务不自动转换为原文，原字段不压平或重命名。

设置 → 本地备份与恢复：

1. “立即备份”显示实际文件位置。
2. “选择恢复”展示确认，检查数据库完整性、外键与 schema 版本。
3. 复制到新的 `recovered-<UUID>.db`，对副本完成迁移验证后原子更新启动选择文件。
4. 退出并重新打开应用后使用恢复副本；原数据库不覆盖。恢复准备完成后、重启前的修改仍在旧数据库，不会自动进入副本，界面有明确提示。

数据库初始化失败时设置中的备份列表与恢复仍不依赖原数据库成功打开。这是本机 SQLite 恢复，不代替 T29 的跨工作空间 JSON 导出导入。澄清时新建的项目在撤销后保留，预览中明确说明；已有后续操作的对象不被静默删除。

## 复现

在仓库根目录依次运行：

```powershell
pnpm typecheck
pnpm test
pnpm test:native
. ./scripts/native-env.ps1
pnpm --filter @praxis/desktop exec tauri build --debug --no-bundle
pnpm test:p0
```

原生 UI 验收必须在内置前端资源的桌面构建后运行；普通 cargo test 可能覆盖调试可执行文件。桌面图形环境与 WebView2 调试端口需可用；受限环境不能访问时，原生验收需在允许启动测试程序的环境执行。本次受限环境曾拒绝 WebView2 调试连接及恢复选择文件的原子重命名；在允许这些操作的环境中重新执行，完整 Rust 与原生验收通过，未降级恢复的原子操作。
