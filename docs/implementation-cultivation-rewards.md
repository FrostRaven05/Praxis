# 自身修炼：关联行动与心愿奖励

2026-10-25（香港时间）。本轮继续自身修炼路线，没有灵宠。它在前两版基础上补齐桌面本机的心愿保存、行动关联、成果确认、奖励解锁和领取链路。

## 使用方式

1. 在“修炼成长 → 心愿与奖励”记录想要的奖励，可填写达成条件，也可先留空。保存心愿不会改变当前阶段。
2. 点击“用于阶段”，核对阶段成果。可以检索并勾选具体行动包；关联时数量固定为选择数，需全部完成。不关联时，按保存后的全局新行动积累计算。
3. 保存阶段设置后，奖励显示“未解锁”。AI 规划采用后也可“带入自身修炼”，默认关联实际采用的任务，并保留成果与奖励条件。
4. 行动条件满足后，由用户确认阶段成果，执行突破。奖励变为“可领取”；点击“记录领取”后为“已领取”。没有自动购买或付款。
5. 改用另一阶段时，旧未完成奖励为“暂存”，可以再次用于阶段，不会消失。编辑当前阶段与选择另一心愿有明确提示。

## 行动与奖励规则

- 一个根任务及其全部子任务作为一个行动包，所有仍存在的叶子任务完成才算完成。关联的是该账号实际存在的根行动包，不能绑定另一账号、失效或已经用于突破的行动。
- 指定行动模式只根据关联行动推进；完成无关任务不会解锁。关联行动被删除、取消或移入别的行动包时显示失效，需要恢复或重新设置。
- 同一行动包只支持一次阶段突破。突破时保留该行动包及已有子任务的身份；拆出子任务或套入新父任务不能重复用于突破。
- 全局模式记录阶段开始时已经完成过的行动身份；旧任务反复切换完成状态不会作为新阶段的新行动计入。
- 行动完成与成果认可分开：达到行动数量后仍需用户确认现实成果。已经确认的突破与已解锁奖励保留，后续任务撤销只校正行动修为。
- 领取、保存和突破均使用固定操作 ID 与版本检查。相同请求重试不重复创建心愿、阶段或领取；事务尾部失败会回滚奖励、阶段和队列写入。
- 心愿使用稳定 ID，激活、解锁与领取沿用同一条记录。规划原文与普通奖励想法记录仍保留；普通记录和成长奖励的后续编辑尚不双向同步。

## 草稿与恢复

修炼设置草稿按服务地址和账号保存在当前设备，支持退出应用后恢复。设置草稿与待确认命令分开存放；原命令未确认时不能被新命令覆盖。成功写入但页面刷新失败时保留原命令，重试读取同一结果。账号改变后停止旧页面写入。

## 数据与兼容

新增迁移 `0025_cultivation_rewards.sql`，记录心愿奖励、当前关联、阶段开始时的行动身份与突破采用的行动身份。旧版成果与奖励迁移保留原 ID，不伪造历史任务关联；旧命令的可选字段在缺省时不写入序列化载荷，已有待确认操作仍可重放。升级继续使用现有迁移前备份机制。

关联过修炼阶段或历史成果的 AI 输出属于已经继续使用的内容，AI 批量撤销会保留它们并报告冲突。普通任务删除和恢复继续走既有流程；修炼页会反映关联失效情况。
