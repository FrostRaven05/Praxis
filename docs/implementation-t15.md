# T15：回收站与恢复

实现日期：2026-10-09。范围为 Windows 本地；同步服务的删除收敛仍由 T27 验收。

## 已实现行为

- 工作中心的“回收站”可以选择任务或项目，预览影响并确认删除。任务删除可保留子项并提升为顶层，或删除整个后代树。项目默认将任务转成独立任务，保持活跃任务之间的父子关系；整项目删除额外要求勾选确认。
- 项目影响预览显示任务数、项目记录链接数和将停止的启用重复模板数。删除只解除相关记录链接，不删除共享记录正文。重复模板停止，恢复项目不会自动重启模板。
- 删除在单个事务内保存原归属、父子关系、记录链接和依赖边，写入软删除标记、审计和待同步操作。提交前检查预览中的任务版本集合；旧预览不会覆盖后续修改。重复提交同一操作幂等。
- 默认项目列表、内容/工作快照、今日列表和工作量统计排除删除内容。取消状态不受影响。T16 搜索须继续使用 `tasks.deleted_at IS NULL` 和 `projects.deleted_at IS NULL`。
- 恢复重新验证所属项目、父任务、分区和依赖图；项目已删除或不再接纳活跃任务时，任务作为独立任务恢复。失效父关系不恢复。仍合法的依赖边和记录链接恢复；其他原始关系保留在删除批次历史中。已提升或转为独立的活跃任务不会被恢复操作挪回原处，避免覆盖删除之后的操作。
- 删除清除项目下一步；恢复不会自动指定下一步。用户需要明确重新选择。
- 本地恢复窗口默认 30 天，可设置为 1–3650 天的整数，带版本冲突检查。按当前设置计算现有条目的截止时间；缩短窗口可能立即使条目到期，延长窗口允许仍保留的条目重新满足恢复条件。到期条目仍可查看，但恢复按钮禁用，后端也会拒绝恢复且不写入待同步操作。`deletion_tombstones` 与 `trash_batches` 独立保存，恢复只记录 `restored_at`，不清除删除历史。未来同步保留策略不能以本地恢复窗口为依据提前删除 tombstone。

## 结构和接口

`0012_trash.sql` 增加项目软删除字段、删除批次和独立 tombstone；`0019_trash_retention.sql` 增加恢复窗口设置和受信起算时间。新删除以本机 `Utc::now()` 保存恢复起算；旧条目迁移沿用过去的事件时间，未来或无效事件时间取迁移当前时间。命令事件时间只用于审计，无法通过伪造 `occurredAt` 延后恢复截止或绕过到期检查。`store/trash.rs` 提供 `trash_snapshot` 与 `trash_command`；后者接收 `TrashCommand`，操作为 `delete`、`restore` 或 `settings`。快照纯读返回设置及版本、每个条目的 `recoveryStartedAt`、`expiresAt` 和 `canRestore`。`TrashView.tsx` 使用稳定操作 ID 的重试器，嵌入工作中心。

项目删除运行时与 T18 的 `recurrence_templates` 联动，因此完整应用应包含 0013 及后续迁移。
