# P1-04 进度、软删除恢复与10秒撤销

日期：2026-11-12。状态：功能实现及针对性存储验证完成；集成界面、完整回归和实际设备结果由本轮后续总验收汇总，不在此提前宣称。

需求依据：[个人版PRD](../prd-mvp-v0.1.md)、[开发计划](../mvp-development-plan-2026-11-09.md)。

## 本次交付

- 个人待办和项目任务行增加可恢复删除，已删除任务折叠显示并可恢复。删除只改变可见性，保留任务ID、状态、说明、截止与完成事实。
- 简单无父无子任务可直接删除；旧层级任务需在原任务入口预览范围，不能在新核心页静默连带删除。旧树形、整项目和复杂恢复保留原回收站入口；原入口即使核心恢复列表为0也可访问。
- 状态变更和简单任务删除在确认后提供10秒撤销。完成、进行中、重开使用同一身份；撤销状态恢复原始状态、等待标记、原因和原完成事实。
- 撤销捕获第一次操作后读取到的版本，不随后台刷新重基。后续编辑、其他任务集合变化或作用域变化会使旧撤销拒绝，不覆盖新内容。提示消失后仍可通过任务状态或已删除列表操作。
- 未知结果保留原命令、操作ID与输入，只能安全重试。确认写入但读取失败时仅重新读取，不重复发送写入。

项目进度继续复用共同个人查询：空项目不显示0/0，全完成不自动结束项目，重开/删除/恢复后刷新；旧树形按有效叶子统计，不双计父子。原项目高级操作、回收站保留期、记录链接和依赖恢复的既有验证路径继续保留。

## 存储与兼容

[个人任务接口](../../packages/application/src/personal-tasks.ts)增加`delete`、`restore`、`undoStatus`，成功变更返回操作ID。原调用可继续忽略返回值。变更由[双端适配](../../apps/client/src/personal-task-adapters.ts)映射到原个人事务与稳定回执，不新增schema迁移。

桌面删除继续使用`trash_command`。新增兼容的`restoreChecked`动作，在原恢复事务中核对删除后版本；原`restore`接口和原回收站行为保留。恢复仍检查原项目、父子、分区和链接，失效归属按原业务规则退为独立任务。新核心页仅接入简单单任务恢复，旧层级须在原回收站预览。

桌面原状态事件保存最小撤销事实及操作后版本，新`undoStatus`只接受同账号、同任务、原操作后的精确版本。撤销重开会重新激活原完成记录，不创建今天的新完成记录。兼容触发器运行后再恢复原`completedAt`，因此未知历史日期保持未知。

手机状态写入保存最小撤销凭据。`workspaceCommand`的完成事实恢复标志须匹配原操作ID、当前版本及原状态字段，才能跳过通常的新完成日期归一化。未知旧完成时刻不会在撤销时变成今天；说明、日期和其他扩展字段不被恢复动作覆盖。明确选择“待办”也会退出旧Todo+waiting组合状态，撤销则恢复原等待标记。

本次没有清理旧奖励、改变经验历史或删除旧内容。P2成长从当前有效任务事实派生，因此完成、重开、删除、恢复和撤销均自然改变有效贡献，旧未知完成日期不计入今天。

## 页面接入

[共同任务页](../../apps/client/src/PersonalTodoHome.tsx)接入状态/删除撤销提示和已删除任务恢复。核心页只增加必要操作；成长条仅在首页显示。供主应用接线的可选回调：

- `onOpenTrash`：原回收站，处理旧复杂恢复。
- `onOpenAgent`：首页下一步建议。
- `onOpenLegacyGrowth`：旧修炼历史；编辑草稿期间阻止导航。

共同页不增加团队、成员或任务分派字段。任务编辑、未确认操作和跨日期分组的草稿保护沿用P1-03。
