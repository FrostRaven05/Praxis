## 本次交付

桌面和手机共用[项目简表单](../../apps/client/src/PersonalProjectForm.tsx)：项目名称必填，目标与目标日期可选。新建只显示这三个字段，无状态、优先级或恢复卡配置；成功后直接打开新项目详情，可继续添加任务。基本信息编辑使用相同表单。

桌面点击侧栏“项目”进入集中列表，仍可从侧栏直接打开项目。手机从原菜单进入“项目”。两端使用同一个[项目列表和进度摘要](../../apps/client/src/PersonalProjectList.tsx)，包含名称、可选目标及目标日期、完成数量和比例、任务逾期数。详情同样显示摘要，并可返回全部项目。

- 空项目显示“还没有任务”，不显示虚构的0%进度；全完成显示100%，不自动结束项目生命周期。
- 旧树形或旧状态项目继续使用P0个人查询的有效叶子统计，明确显示统计口径；取消任务不进入有效分母。完成与重开后重新读取，结果使用同一规则。
- 目标日期与任务截止分别处理：项目目标日期过期不会凭空增加逾期任务数。日期与原确定时刻沿用个人查询的时区规则；页面每15秒重新计算时间相关摘要。
- 列表按项目自身最近已知更新时间降序排列，缺失时回退创建时刻和稳定ID。桌面从原项目事件、项目内容事件和同步项目记录读取时间，手机使用原实体的更新时间；不把读取时刻当成修改时刻，不增加数据库字段。此排序描述项目记录更新，不将每次任务更新伪装成项目元数据修改。
- 已归档项目默认收起，可勾选显示后打开。单个旧树形异常显示警告；无法解释日期时保留项目卡片并显示查询警告，不修改原数据或渲染虚假进度。

桌面状态、归档与分区保留在详情“更多项目设置”；修复原入口只会返回项目详情的问题，现在打开既有“项目与分区”管理页。手机保留“编辑与恢复卡”及原分区、恢复资料。原看板、甘特图、每日安排、修炼和AI功能入口继续保留。

## 保存、重试与兼容

[共同保存逻辑](../../packages/application/src/personal-projects.ts)为每个打开的表单保存一份基础版本、账号作用域和待确认命令。桌面复用原`save_project`事务，手机通过[字段适配](../../apps/client/src/personal-project-adapters.ts)复用`workspaceCommand`，并检查原工作空间。

1. 必填或日期校验失败时不写入，输入保留。
2. 保存中阻止重复提交。明确业务或版本拒绝后保留可编辑输入，可取消并重新读取。
3. 回包丢失等结果不明时冻结原输入、项目ID、操作ID、版本和发生时刻，提供“重试保存”；重试原命令并查询原回执，不创建第二个项目。未确认时保护取消和页面内导航，账号变化时要求返回原作用域处理。
4. 已确认保存但详情读取失败时显示“项目已保存”和“重试打开项目”，后续只重新读取，不再发送保存命令。
5. 项目基本编辑保留原优先级、生命周期、归档、恢复卡及未知扩展；手机只替换名称、目标和目标日期对应字段。原版本过期时拒绝覆盖，已有任务身份和归属不改变。

手机项目页新增同步事件读取，编辑期间延后应用该快照；同步完成或恢复前台后可更新进度。桌面编辑实例不再因为背景读取中项目缺失而重建成“新建”表单。

未新增迁移、清空队列、操作真实用户库或删除旧数据。桌面schema仍为25，手机仍为5。生产API和账号同步协议没有变化。
