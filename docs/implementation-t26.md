## 可以复用的接口及必要扩展

- `ContentCommands` 和 `ContentAction::Record`：保留稳定操作 ID、记录 ID、预期版本和错误重试机制。需增加同步协议中的基线身份或基线字段值；不能仅从客户端时间或当前内容猜测共同祖先。
- `Store::content_command`、`queue_operation`：复用实体、事件、待发送操作同事务提交。冲突入库、接收游标更新和解决提交也需要明确事务边界；未落库的冲突不得被游标跳过。
- `productivity_command` 及既有数据库约束：复用任务终态、父子、项目归属和时间字段的校验。字段独立合并后仍须按业务组校验完整候选对象，不能逐字段绕过规则。
- 现有 RecordEditor：可复用文本编辑控件，但需要独立的双方内容展示、手工合并草稿和持久化冲突入口。保留本机或另一端必须展示明确内容，不能把设备时钟更晚直接作为胜者。

同步层需要明确共同基线的保留/获取办法、冲突稳定身份、双方版本及展示时间、解决状态和解决操作幂等规则。冲突内容应按同一工作空间权限保护，正文不进入诊断日志。源版本在解决过程中改变时，应保留用户合并草稿并重新展示差异。
