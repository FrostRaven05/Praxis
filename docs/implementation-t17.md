# T17 项目检查与手动周回顾

已实现 Windows 桌面本地范围，入口为今日与近期中的「项目检查与周回顾」。不依赖 AI 或网络。

## 用户行为

- 专用项目检查读取活跃且未归档、未删除的项目，显示未指定下一步、复查日期已到、真实期限逾期、达到用户设置天数未记录推进。阈值默认 7 天，可保存 1–365 天。
- 日期期限在工作区时区的日期结束后算逾期；精确期限与当前时刻比较。今日的日期期限不会被提前算作逾期。
- 推进证据包括关联的 progress 记录、仍处于完成状态的任务完成时间，以及用户显式保存恢复卡的 context 事件。恢复卡因系统清空下一步而变化不会伪装为人工推进。跨偏移时间戳统一为 UTC 后比较。没有证据时从项目创建日起计算，始终说「未记录推进」，不推断用户实际没有工作。
- 手动填写期间、推进成果、阻塞、停止/暂停事项、下周重点，并使用稳定项目 ID 关联项目。项目更名后仍能打开同一项目。已归档项目可以保留引用；项目删除后明确提示，保存前需取消不存在的引用。
- 回顾保存为独立 `record_type=review` 记录，结构字段由 `weekly_reviews` 保存，正文同步生成可阅读文本，关联复用 `record_links`。不创建任务，不变更项目状态。普通记录列表提供「编辑周回顾」跳转，防止普通编辑器破坏结构字段。
- 新建与编辑支持离线保存、重启读取。未保存正文会锁定工作区导航并提示放弃；保存中的命令去重，结果未确认时相同内容重试复用操作 ID。

## 一致性与验证

迁移 `0018_reviews.sql` 新增检查设置、回顾结构及正文一致性约束。`review_command` 将结构、记录、关联、事件和 outbox 写入同一事务；版本冲突、无效引用失败时整体回滚。读取诊断不会改变任务或项目。

在 Store 公共接口 seam 完成 4 项定向测试：

1. 保存独立记录、不生成任务、幂等重试、重启恢复。
2. 工作区日期/精确期限、不同 RFC3339 偏移的最新证据、用户阈值。
3. 离线补充编辑、稳定项目链接、版本/引用冲突无部分写入、专用编辑保护。
4. 恢复卡事件作为推进证据、暂停项目排除、阈值重启保存。

`cargo test --test reviews --locked`：4/4 通过。`pnpm typecheck` 通过。缺失接口、不同偏移排序和恢复卡推进证据均先观察失败测试再修复。最终全量回归、真实桌面验证及双轴代码评审由集成任务统一执行，不在此重复声称完成。
