现有项目已经具备个人任务工作台、项目管理、账号同步、AI 规划草稿及桌面修炼的实现基础。达到本次 PRD 的主要工作是补齐共享项目与任务负责人模型，重组轻量页面，统一进度与成长规则，并将 AI 写入升级为服务端可核对的协作操作。应复用已有业务与存储能力，在增量改造中保留历史内容。

本次完成代码阅读、TypeScript 类型检查、完整现有 TypeScript 测试和 Rust 存储测试。没有执行桌面或 Android 图形界面验收、真实模型请求、线上部署检查；当前运行中的服务、安装包和真机表现不属于已验证结论。历史实施记录只作为背景，不能替代本次验收。

## 需要保留的实现

### 任务身份和可靠写入

保留任务与项目稳定 ID、版本字段、操作标识以及任务和每日安排的引用关系。已有完成、撤销、项目批量写入和删除恢复使用事务或防重命令，应继续作为改造基础。我的待办新增查询投影，不另建一份可独立修改状态的待办任务。

现有服务端允许不同账号拥有相同实体 ID，并依靠 owner 隔离。共享资源需要明确的新作用域标识，不能直接取消 owner 条件，也不能把所有成员的数据统一改归项目创建者后继续沿用全部个人查询。

### 离线与账号基础

复用现有账号、按账号和服务隔离的本地数据路径、SQLite、同步队列、冲突记录和备份机制。新的成员加入与授权变更需要服务端确认；本地已保存与其他成员已收到继续分开展示。

浏览器当前为禁止保存的预览路径。首版计划优先沿用现有 Windows 与 Android 客户端，不把浏览器预览标记为可写 Web 端，不在本轮另建完整 Web 存储系统。

### AI 与旧修炼资产

保留 AI 结构化协议校验、模型侧不直接执行写入、按账号隔离的草稿、相关版本检查、事务应用及业务回执核对。保留旧修炼、心愿和已领取奖励的历史身份与记录。

甘特、看板、子任务、收件箱、记录、习惯、重复、回顾、专注、统计和管理后台属于已有资产。本轮暂停扩展，默认入口按 PRD 收敛，并保留次级兼容入口；不执行破坏性删除或全量重写。

## 需要调整的关键规则

### 页面和日程语义

当前今日页依赖每日安排，移动端默认清单也按执行日或截止日筛选；未安排且无日期的项目任务不会自然形成 PRD 要求的完整个人待办。新首页必须使用负责人和访问范围查询，覆盖无日期任务。

项目列表当前主要是侧栏名称列表，项目详情还包括恢复卡、视图切换和层级操作。新默认路径保留项目列表与简洁详情；已有复杂内容放入次级入口。项目输入框已有 Enter 保存和焦点恢复，需补中文输入法状态保护的测试和实际验收；仅凭 form 提交代码不能认定输入法已通过。

### 日期和进度

当前任务详情支持带时区的瞬时时间，移动同步包含 dueDate 等字段；项目任务接口还需统一补齐列表所需日期投影。新增日期级截止需要明确类型和项目时区，保留原有瞬时时间及计划日期，不能靠截取字符串覆盖旧值。

当前详情进度累加叶子任务，项目查询按创建时间排序，侧栏没有完成比例和逾期摘要。新版平铺项目按 PRD 计算；旧层级项目保留可辨识的兼容视图与原统计口径。迁移说明须给出历史父子任务、waiting、blocked、cancelled 的展示与统计规则，避免简化 UI 时静默丢状态或把父子重复计入。

项目完成数量与成果验收继续分开。全部任务完成仅产生任务反馈，不自动改写旧项目生命周期。

### 成长口径

当前 cultivation.rs 将根任务及其叶子作为一个行动包，经验为有效包数量乘 10；境界来自突破次数，完成阶段和领取奖励还有独立操作。删除已完成内容后保留旧经验是代码和测试明确维护的旧规则。

新 PRD 要求每个有效完成任务产生一份经验，归完成时负责人，撤销或删除时回退，每百 XP 直接升级。实现需要新的规则版本和归属记录，不能只改前端显示公式，也不能直接修改旧奖励余额。

建议保留旧修为与已领取奖励为历史，按新版当前有效任务重建独立 XP 投影，不将两套经验相加。无法确认历史完成日期时不伪造成今天完成。新版迁移样本和用户可见口径说明列为前置交付。

### AI 上下文与执行

当前 AI 为 clarify、decompose、resume 三种模式；提案包含估时、依赖和奖励，采用契约没有负责人及截止日期。resume 主要给出一个项目内 suggestedTaskId，还允许生成新步骤，尚不等同于只读的跨项目三项建议。

当前 read_project 与 list_ready_tasks 使用客户端提交的资料快照，已有版本与范围校验。协作版本需要经项目权限检查的真实查询与确定性统计；不能只修改 Prompt 就把快照解释为服务端最新数据。

生成记录在 API 保存，但应用回执主要在设备本地，SQLite 迁移也明确标注该边界。现有同设备防重不能作为跨设备共享项目只采用一次的保证。新增服务端业务回执与确认记录，并让新协作路径通过统一命令服务写入。

当前为最多 4 轮模型调用、8 次工具调用和默认 45 秒超时，已具备预算与取消机制。PRD 的 6 轮和 60 秒可通过内部策略调整；优先补业务边界，避免为更换框架重做已有机制。服务重启时运行记录会标记中断失败，完整续跑仍需保存明确执行阶段和真实结果。

保留批量写入原子性。失败通常可以保持整批未写入；只有确实存在已生效项时才呈现部分完成，不为展示状态主动拆散事务。

## 核心新增能力

| 新增能力 | 必须覆盖的范围 | 不可省略的验证 |
| --- | --- | --- |
| 共享项目模型 | 创建者、成员、创建人与负责人分离、项目时区、操作者 | 非成员无权读取或写入 |
| 邀请和成员管理 | 登录后主动加入、链接撤销与重置、移除及未完成任务转交 | 旧链接失效、转交与撤权的原子结果 |
| 共享命令与同步 | 资源级授权、版本、防重回执、按成员范围的增量数据 | 两账号不同设备读到同一任务，个人资料不外泄 |
| 我的待办查询 | 负责人、项目访问权、真实截止日期分组、无日期任务 | 无需安排到今日即可出现，转交后归属正确 |
| 新版 XP 与等级 | 完成时领取人、撤回、删除与恢复、防重、历史口径 | 不因重试或更换负责人重复记分 |
| 轻量成长组件 | 首页经验条、非阻塞反馈、隐藏和减少动效 | Windows 与 Android 规则一致 |
| AI 协作执行 | 最新权限上下文、成员日期预览、绑定确认、服务端回执 | 撤权、刷新、并发采用和结果不明均可核对 |
| 只读进展建议 | 系统统计、个人跨项目查询、最多三项任务建议 | 只读模式没有任务写入权限 |

成员移除必须立即在服务端拒绝后续访问。完全离线设备已缓存的资料无法依靠远端命令即时擦除；客户端下一次联网或恢复会话时应重验成员资格，锁定或清理对应缓存，并拒绝撤权后的排队写入。实现和验收不能承诺离线数据即时远程撤回。
