# Praxis 个人管理首版产品需求文档

版本：v0.2 个人版  
更新：2026-11-11  
产品边界：整个项目仅面向个人管理  
适用终端：Windows 与 Android，沿用现有账号和同步能力

Praxis 帮助用户把自己的目标组织成项目，拆成可执行任务，在个人待办中找到下一步，并通过进度、成长修炼和 AI 辅助持续推进。

团队协作、成员邀请、任务分派、共享项目和组织权限均从产品路线移除。同一账号的跨设备同步属于个人管理；不同账号的数据始终隔离。此前团队方向的文档和服务端切片仅作[历史归档](archive/team-prototype-2026-11-10/README.md)。

## 产品价值与首版原则

首版解决三个问题：目标过大不知道如何开始，多项目并行时不知道接下来做什么，以及执行后看不到进展。

- 项目只填写名称即可创建，任务只输入标题即可保存。
- 所有任务默认由自己执行，不显示负责人选择、成员头像或团队配置。
- 项目、个人待办和 AI 使用同一条任务，项目归属变化不创建副本。
- 日期和说明可后补；已有计划日期与真实截止时间保留各自含义。
- 完成、撤销、删除、恢复和 AI 采用结果均可核对。
- 成长与 AI 融入现有页面，不增加必经的打卡、领奖或聊天步骤。

## 核心用户流程

核心闭环为：创建个人项目 → 拆解任务并归属项目 → 查看个人待办 → 更新任务状态 → 查看项目进度与个人成长。

| 流程         | 页面与操作                                                 | 系统反馈                                                 |
| ------------ | ---------------------------------------------------------- | -------------------------------------------------------- |
| 创建项目     | 项目列表点击创建，输入名称，可选补充目标及目标日期         | 保存成功直接进入项目；空状态提供添加任务和 AI 拆解       |
| 拆解任务     | 项目详情输入标题，按 Enter 连续添加；也可使用 AI 草稿      | 默认归属当前项目，状态待办；保存后继续输入，失败保留内容 |
| 组织任务     | 在个人待办添加独立任务，或在详情选择所属项目与可选截止日期 | 同一任务出现在相应视图；无需先加入今日，也不要求日期     |
| 更新状态     | 列表直接切换待办、进行中、已完成；完成一次点击             | 个人待办、项目统计和经验同步更新，提供10秒撤销           |
| 跟踪进度     | 在项目列表查看摘要，进入详情查看具体任务                   | 展示完成数量、比例及逾期；空项目有明确引导               |
| 查看个人待办 | 默认首页查看自己的跨项目未完成任务并直接操作               | 自动分组逾期、今天、之后、未设日期，已完成默认折叠       |

中文输入法组词时按 Enter 只确认文字，不提交任务。保存中防止重复操作；失败保留输入与原重试标识。

## 页面结构

首版保留两个主导航、三个核心页面：

    Praxis
    ├─ 我的待办 默认首页
    │  ├─ 个人等级与经验
    │  ├─ 未完成任务与已完成折叠区
    │  └─ 下一步建议
    ├─ 项目
    │  ├─ 项目列表
    │  └─ 项目详情及任务列表
    └─ 账户与基础设置 次级入口

任务详情与 AI 使用侧栏，小屏使用同内容的全屏面板。项目创建使用短弹窗。既有收件箱、习惯、日历、记录、回顾等个人能力保留兼容访问，本轮不要求扩展或全量重做。

### 我的待办

展示当前个人账号全部未完成任务，包括所有个人项目和独立任务。不以是否安排到今天作为出现条件。

按截止日期自动分组，空分组不显示；组内日期升序，同日按创建时间，无日期按创建时间。任务行显示标题、状态、可选日期与项目名称。点击项目可回到上下文，点击标题打开详情。

### 项目列表与详情

列表显示名称、完成数量与比例、逾期数，按最近更新排序。无任务时显示“还没有任务”。

详情首屏为名称与可选目标、进度摘要、任务列表和行内添加。目标、日期与说明无需先填完整。已完成默认折叠。旧层级、看板和排期通过兼容入口保留，不挤占新默认任务列表。

项目字段为名称、可选目标与目标日期。任务字段为标题、状态、可选项目归属、截止和说明。账号归属在系统内部维护，不作为任务编辑项。

| P-TASK02 | 任务整理   | 标题、可选项目、日期和说明，无任务分派         |
| P-TASK03 | 状态与恢复 | 三态、快捷完成、重开、软删除、恢复和版本化撤销 |

| P-PROG01 | 项目进度   | 完成数量、比例、逾期、空状态及全完成反馈       |
| P-GROW01 | 成长修炼   | 个人经验、等级、反馈，完成与回退防重           |
| P-AI01   | AI 拆解    | 个人目标、可编辑草稿、一次确认创建             |

## 状态 日期与进度规则

新任务固定为待办、进行中、已完成，可以直接从待办完成。完成后可重开；短提示消失后仍能在详情重开。撤销检查版本，不能覆盖后续编辑。

删除使用可恢复删除，删除与恢复均更新统计及经验。任务从一个项目移到另一个项目保持原任务 ID，不重复记分。

日期级截止按个人工作空间时区的自然日判断，次日零时后逾期。旧确定截止时刻保留精度和显示时区；每日安排、项目目标日期与截止各自保存，不自动覆盖。

新平铺项目按未删除任务计算完成比例，百分比四舍五入。空项目 percentage 为 null，不显示0/0；全部任务完成仅显示任务完成反馈，不自动认定项目成果验收或归档。

旧 waiting、blocked、cancelled 与树形任务保持原语义和兼容入口。旧树形进度明确标为有效叶子统计，不静默转为平铺统计或双计父子。

## 成长修炼与界面风格

成长条放在个人待办顶部，显示等级、当前级经验和今天完成数量，任务列表仍是主体。

- 每个当前有效已完成的个人任务贡献10 XP，同一任务最多一份。
- 撤销、重开、删除时撤回该贡献，恢复有效完成状态时恢复一份。
- 每100 XP升一级；等级为1加上 XP除以100的整数部分，当前级经验为余数。
- 项目归属变化不转移或重复计算贡献。未知历史完成日期不伪造成今天。
- 旧行动包修为、境界和已领取奖励保留历史，新 XP 不与其叠加。

只提供个人反馈，不使用排行榜、强制连续打卡、商城、装备或功能解锁。成长展示与动效可关闭，不影响任务和经验记录。

界面采用轻 RPG 任务日志风格，沿用 DESIGN.md 的组件及明暗主题，加入紧凑等级徽章、经验条和轻量向导。项目、任务、截止等名称保持直白。完成和升级使用约1秒内的非阻塞动效，同时提供文字或图标反馈。

## AI Agent

界面使用一个“行动助手”，游戏化形象可称同行向导。用户无需选择角色、模型、工具或工作流。

| 能力           | 工作流程                                                                             | 边界                                                   |
| -------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 目标拆成任务   | 读取当前个人项目及已有任务，生成少量具体结果，展示标题、可选日期与说明，用户一次确认 | 无成员、负责人或分派字段；未确认不进入待办、进度和经验 |
| 看进展找下一步 | 查询个人真实任务和系统统计，给出最多三项建议及理由                                   | 建议关联现有任务并显示读取时间，不自动改状态或日期     |

任务草稿默认约3至7项，按目标规模调整，优先复用已有任务。信息不足时只问影响结果的关键问题。完成标准可写入说明，不增加必填表单。

运行链路为：读取必要个人上下文 → 生成建议或草稿 → 用户确认具体变更 → 通过现有个人业务命令执行 → 核对实际结果 → 刷新页面。统计由程序计算，AI解释事实和提出建议，不自行认定实际任务已经完成。

账号与存储身份来自可信会话，资料正文和模型输出不能授予权限。沿用现有版本校验、结构化协议、有限循环、超时与取消，不为首版搭建多角色配置平台。

首版草稿按账号与设备保存，在生成设备检查和采用；正式任务通过现有同账号同步到其他设备。跨设备采用同一草稿不在首版开放范围。重试使用稳定操作和任务 ID，未知结果先查原采用回执；停止不自动回滚已提交内容。

生成失败、离线或服务不可用时保留输入，手动五个核心场景继续可用。未接通真实模型时，界面说明实际状态，不能将模型替身验证标为真实 AI 已交付。

## 数据兼容与账号边界

沿用现有个人 owner、任务 ID、本地事务、同步队列、账号与服务隔离、冲突保留和备份恢复。相同账号在两个设备读写同一份任务；不同账号即使实体 ID 相同，资料也独立。

个人数据兼容只整理当前 owner 内的项目、任务、日期、旧状态、修炼和 AI 回执，不将个人资料迁入共享作用域。不自动分享链接记录、不新增成员关系、不修改真实用户库来完成开发验证。

本地已保存、待同步、已同步和失败分开反馈。迁移先在合成库与备份副本验证，保留旧内容、未同步操作和恢复路径。此前团队代码已移出生产编译路径，历史数据库中已有未知表继续保留。

## 版本边界

首版包含本文件的个人闭环、轻量成长和两项 AI 能力。后续方向仅面向个人：任务模板、标签与重复、个人日历及专注、回顾、语音收集、个人资料检索。既有相似功能保留访问，按真实需要改进。

团队协作、邀请、成员分工、项目共享、团队权限和绩效功能不进入本项目路线。按[个人版开发计划](mvp-development-plan-2026-11-09.md)推进；已有[个人数据兼容基线](p0/personal-data-compatibility.md)作为后续实现约束。
