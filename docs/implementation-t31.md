## 前置解除后的实施边界

继续复用 `ContentCommands.save` → `content_command` → `Store::content_command`，以及 `readContent` → `content_snapshot` 的记录读写链路。复用 `RelatedRecords`、记录关联校验、操作重放、乐观版本检查和事务事件，不提前建立独立 Decision 实体。

以下字段是后续实现建议，不是已经落库的契约。实施时再冻结模板版本和存储映射，避免把现有自由正文强行解析为结构数据。

| 模板 | 建议字段 |
| --- | --- |
| 策略卡 | `diagnosis` 问题诊断、`guidingPolicy` 指导方针、`coherentActions` 配套行动、`explicitNonGoals` 明确不做、`changeOrStopConditions` 调整或停止条件 |
| 决策记录 | `knownFacts` 当时已知事实、`interpretation` 自己的解释、`alternativeInterpretations` 替代解释、`expectedOutcome` 预期结果、`checkDate` 检查日期、`actualOutcome` 实际结果、`judgmentUpdate` 判断更新 |

策略卡按项目提供可选入口，默认折叠，不把填写策略设为任务创建的前提。决策继续作为 Record 模板表达；模板应有明确标识和版本，兼容旧 `decision` 自由正文。策略是否使用关联 Record 或项目的可选扩展字段，应在实施时按已验收同步、导出契约确定；当前恢复卡字段不能被挪用或覆盖。配套行动不自动创建任务，检查日期不自动改动任务期限或安排。

## 后续验收清单

- 策略卡默认折叠；空策略不会阻止创建项目或任务；填写后退出、重启能保留全部字段。
- 决策先保存用户判断，随后另次更新实际结果和判断；历史能看到各次原始判断及更新时间。AI 关闭或未配置时整个流程可用。
- 原有自由正文决策可继续打开和编辑；模板字段升级不丢失旧内容，不悄悄将正文转换成结构字段。
- 同一记录关联多个有效项目或任务时只保存一份正文；变更关联、删除与恢复不产生重复记录或悬空有效引用。
- 两端离线编辑、重试及冲突处理沿用已验收的同步契约；保留版本历史，不能只证明 outbox 有记录便判定通过。
- T29 JSON 导出包含模板标识、版本、字段、记录关联与历史；恢复到新工作空间后逐字段及逐引用核对。普通导出不包含服务凭据。
- 使用端到端用例验证策略与决策编辑、重启、历史回看、跨端同步和导出恢复；以实际运行证据验收，不能以本文替代测试。
