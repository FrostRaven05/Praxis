状态：M0 规格基线  
需求来源：[首版 PRD](../prd-mvp-v0.1.md)与[开发计划](../mvp-development-plan-2026-11-09.md)

本规格冻结 M1 所需的身份、协议和兼容规则。领域类型位于 [contract.ts](../../packages/application/src/mvp/contract.ts)，兼容规则的可执行参考位于 [compatibility.ts](../../packages/application/src/mvp/compatibility.ts)。这些新模块没有接入现有应用入口、路由或存储，本阶段不执行产品数据迁移。规范中的新 API 和表是后续实现目标。

## 身份和资源边界

| 身份或标识  | 来源及含义                             | 不可混用的对象             |
| ----------- | -------------------------------------- | -------------------------- |
| serviceId   | 当前连接服务的稳定身份，随账号绑定保存 | 用户可编辑的项目名称       |
| actorId     | 服务端认证所得用户                     | 请求中的自称身份或模型输出 |
| local owner | 现有设备账号数据隔离及外键范围         | 项目创建者、任务负责人     |
| creatorId   | 项目首次创建者，首版不转移             | 当前任务负责人             |
| createdBy   | 最初建立任务的操作者，转交后不改变     | assigneeId                 |
| assigneeId  | 当前承担任务的成员                     | 操作者、经验领取人         |
| recipientId | 有效完成时冻结的任务负责人             | 完成后改分配得到的新负责人 |

个人资源身份为 serviceId、personal、ownerId、实体类型、实体 ID 的元组；项目资源身份为 serviceId、project、projectId、实体类型、实体 ID 的元组。元组按 JSON 数组编码，不用简单分隔符拼接。两位用户历史上拥有相同实体 ID 仍然是不同资源，两个服务上的相同项目 ID 也不同。

本地缓存继续按服务与登录账号隔离；缓存内部再以作用域和实体 ID 区分资源。不同成员的缓存是同一权威任务的副本，不能各自产生独立的业务任务。

旧项目登记使用唯一映射 serviceId、legacyOwnerId、legacyProjectId → projectId。projectId 由服务分配并保存，一次登记后不随重试变化；原任务 ID 在该项目作用域内保留。不得只按 legacyProjectId 合并两个 owner 的项目。未登录的本地资料先绑定并核对所属账号，不能猜测它属于另一位登录用户。

## 项目成员和邀请

| 行为                                 | 创建者             | 当前成员 | 非成员                             |
| ------------------------------------ | ------------------ | -------- | ---------------------------------- |
| 查看项目及项目任务                   | 允许               | 允许     | 拒绝                               |
| 创建、编辑、分配、更新或删除项目任务 | 允许               | 允许     | 拒绝                               |
| 修改项目名称、目标和目标日期         | 允许               | 拒绝     | 拒绝                               |
| 生成、重置或撤销邀请                 | 允许               | 拒绝     | 拒绝                               |
| 移除成员                             | 允许，不能移除自己 | 拒绝     | 拒绝                               |
| 预览有效邀请对应的项目名称           | 允许               | 允许     | 持有效链接允许，正文和任务仍不可见 |

新项目创建后自动建立创建者成员记录，accessGeneration 从 1 开始。首次创建命令使用 expectedAccessGeneration 为 0。正常成员命令带上当前 accessGeneration；成员移除和重新加入递增该用户的代数，不能让旧确认在重新加入后复活。

邀请默认七天有效，服务端只保存令牌摘要，原令牌只出现在生成结果及用户复制的链接中，不写入 AI 上下文或日志。重置时原链接立即失效。有效链接允许用户登录后主动加入，不自动加入、不允许自选角色；重复加入返回已有成员关系。成员仍需当前有效认证。

移除成员前读取其全部未完成任务及版本，预览默认转交给创建者。提交时再次核对成员版本及完整任务集合，在一个事务内完成转交、移除和访问代数更新；期间出现新增任务或版本变化则整体拒绝并要求更新预览。已完成任务保留负责人及经验历史。创建者自移除与所有权转移不开放。

撤权立即影响服务端查询、写入及回执读取。断网设备已缓存的资料无法即时远程擦除；下次联网或恢复会话时重验资格，锁定或清理失权范围，拒绝其排队写入。成员移除不能通过普通任务编辑间接绕过。

## 命令和 API 契约

协议标识为 praxis-project-v2，与现有 v1 个人同步并存。现有个人接口仍按认证 owner 隔离，不能用于读写新共享资源。

命令信封包含 protocol、operationId、deviceId、projectId、expectedAccessGeneration、name、payload。允许的 payload 由 TypeScript 判别联合固定。actorId、权限、服务端时间、完成领取人不在客户端信封中；运行时从认证、当前任务和服务端时钟计算。

| 后续接口                              | 行为和约束                                                 |
| ------------------------------------- | ---------------------------------------------------------- |
| POST /v2/projects                     | 创建项目，建立创建者成员，名称非空，项目时区自动取账号时区 |
| POST /v2/projects/:projectId/commands | 按 contract.ts 的命令提交，路径与信封项目一致              |
| GET /v2/projects/:projectId/snapshot  | 授权后的项目、成员、任务及确定性统计，附数据读取时间       |
| GET /v2/me/tasks                      | 仅当前负责且有访问权的任务，保留个人独立任务和无日期任务   |
| GET /v2/me/project-changes            | 当前账号可访问的项目增量变化及撤权信息                     |
| GET /v2/commands/:operationId         | 核对当前用户发起的业务结果，仍检查资源权限                 |
| GET /v2/invitations/preview           | 使用链接令牌预览项目名称，不返回任务或成员资料             |
| POST /v2/invitations/join             | 认证后的用户携令牌主动加入，不能伪造邀请角色               |

执行顺序固定为：协议和参数校验 → 身份与设备校验 → 当前资源和成员授权 → 防重回执核对 → 版本、成员与确认条件检查 → 事务写入 → 保存事件与回执 → 返回结果。查询业务回执同样先授权，不能通过重放结果泄露失权项目内容。

防重键为 serviceId、actorId、operationId；摘要覆盖协议、项目、命令名及规范化 payload。同键同内容返回原回执，同键不同内容返回 OPERATION_CHANGED。一个用户跨设备采用同一个 runId 另有唯一约束，不能换 operationId 重复采用。deviceId 必须绑定当前认证会话，不能自报。

任务创建人由操作者填入，初始状态固定 todo；未选择负责人时由运行时填当前用户。新任务只接受日期级截止。编辑旧任务未修改截止时刻时保留原 instant 值；用户主动改为日期级截止才转换。提交新状态不接受调用方传入 completedAt、recipientId 或 XP。

版本均为非负整数，首次版本 1；更新检查 expectedVersion。删除、恢复、状态切换和成员变更的副作用及回执在同一事务内提交。失败不返回成功回执。结果不明先按原 operationId 查询，再以原内容重试。

| 错误                  | 含义和客户端处理                              |
| --------------------- | --------------------------------------------- |
| UNAUTHENTICATED       | 重新认证，不继续发送排队变更                  |
| RESOURCE_FORBIDDEN    | 锁定失权项目，不盲目重试                      |
| PROTOCOL_UNSUPPORTED  | 保留本地输入，提示使用支持该协议的客户端      |
| VERSION_CONFLICT      | 保留输入，读取最新内容并明确解决冲突          |
| OPERATION_CHANGED     | 恢复原命令核对，不用旧 operationId 提交新内容 |
| MEMBER_REQUIRED       | 负责人不是当前成员，重新选择                  |
| CONFIRMATION_REQUIRED | 生成具体变更预览并请求一次确认                |
| CONFIRMATION_STALE    | 展示相关变化或过期原因，重新确认              |
| INVITATION_INVALID    | 链接已过期或撤销，不开放项目正文              |

未授权资源对外不区分不存在与无访问权，响应不能暴露项目存在性或私人内容。

## 存储与同步目标

下表描述 M1 和 M3 的存储约束，不是本阶段执行的迁移脚本。新增表不改写历史迁移校验值，不直接替换现有个人表的 owner 外键。

| 逻辑记录                         | 主键与约束                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------- |
| shared_projects                  | 服务内 projectId 唯一，creatorId 不变，保存时区、版本、统计模式和更新时间             |
| project_members                  | projectId、userId 唯一，保存 role、state、version、accessGeneration；只允许一位创建者 |
| project_tasks                    | projectId、taskId 唯一；保存创建人、当前负责人、三态、截止类型、版本和软删除信息      |
| project_legacy_bindings          | serviceId、legacyOwnerId、legacyProjectId 唯一且映射不可随重试改变                    |
| project_invitations              | 随机令牌摘要唯一，保存失效和撤销状态，不保存原令牌                                    |
| shared_command_receipts          | actorId、operationId 唯一，命令摘要不可变；保存结果版本与提交时间                     |
| task_completions                 | 保存操作者、冻结领取人、真实或未知完成时间、来源和撤销事实，不改写历史领取人          |
| task_xp_contributions            | 每个作用域内任务最多一份有效贡献，历史完成和撤回记录可追踪                            |
| ai_confirmations 与 ai_adoptions | 绑定用户、项目、runId、草稿摘要和访问代数；同一用户 runId 最多采用一次                |
| project_changes                  | 项目内单调变化序列；用户读取前按当前权限筛选，不复用个人 owner 游标伪装团队数据       |

客户端保存同步 cursor 与访问集合代数。访问集合变化时服务端可要求重建授权投影，并显式下发 revokedProjectIds。撤权只是该账号缓存失效，不向其他成员广播任务删除。尚未支持 v2 的客户端不下载共享资源，也不能将新字段降级覆盖为空。

## 新旧状态与层级兼容

| 旧数据                       | 聚焦版兼容展示                         | 写入与统计                                             |
| ---------------------------- | -------------------------------------- | ------------------------------------------------------ |
| todo、in_progress、completed | 待办、进行中、已完成                   | 新任务只使用这三态                                     |
| waiting                      | 保留等待标签、等待对象和原因           | 不自动转 todo；在兼容视图操作                          |
| blocked                      | 保留阻塞标签和原因                     | 不自动转 todo；在兼容视图操作                          |
| cancelled                    | 保留取消状态及历史入口                 | 不当作完成，不纳入旧叶子分母，不偷偷改成删除           |
| 带父子关系的项目             | 保留树形兼容视图，明确标为叶子任务进度 | 延用现有 projectTree 的有效叶子计算，不把父子各算一次  |
| 新建平铺项目                 | 简洁任务列表                           | 每条未删除任务计一次，已完成数除以总数，百分比四舍五入 |
| 空项目                       | 添加任务后开始跟踪                     | percentage 为 null，全部完成为 false                   |
| 全部任务完成                 | 全部任务已完成                         | 不改写项目成果、归档或生命周期                         |

不得把旧层级数据直接交给平铺统计。未知状态、重复任务 ID、循环或缺失父节点返回可处理的兼容错误，保留源数据供恢复，不按空项目处理。

## 日期与时区兼容

| 类型         | 保存与判断                                                                |
| ------------ | ------------------------------------------------------------------------- |
| 新日期级截止 | kind=date、date、timeZone；项目时区在创建时自动固定，首版不开放改时区配置 |
| 旧确定时刻   | kind=instant、atUtc、displayTimezone；保留原精度、时区和旧字段            |
| 每日安排     | 单独保存计划日期，永不作为默认截止日期                                    |
| 项目目标日期 | 只表达项目期望，不覆盖任务截止                                            |
| 无截止       | 保持 null，进入未设日期分组                                               |

日期级任务在项目当地该日期结束前均不逾期，跨到下一自然日后逾期，不通过加固定 24 小时推算。夏令时当天可有 23 或 25 小时。旧时刻在 now 大于或等于 atUtc 时逾期；尚未到期时按原显示时区判断今天或之后。今天完成数按查看者账户时区计算，不能截断 UTC 字符串。

原始 deadline、deadline_value、deadline_time_zone、plan_value 和每日安排记录保留。在未来迁移时生成新投影和来源映射，不回写格式化后的展示值。无效历史时间进入兼容错误清单，不能伪造当前时间替代。

## 新版 XP 与旧修炼

规则标识为 task-xp-v1，独立于旧 cultivation_state.rules_version。初始 XP 根据当前有效已完成任务重建，未删除、非取消且非摘要父任务的实际行动才可贡献；旧树形项目取实际叶子，避免父子同时记分。已删除的旧已完成行动保留其旧 credits 历史，新版不计入。

历史独立任务的负责人映射所属账号，并记录 legacy-owner-inferred。无法还原的完成时间为 null；它可以贡献有效 XP，但不贡献今天完成数量。旧 owner 是本地身份时先完成账号归属登记，不能直接作为另一账号的领取人。

每个有效任务贡献 10 XP，领取人为完成当时负责人。改负责人不转移既有贡献；重开撤回原领取人的贡献，再次完成创建新完成事实。删除撤回，恢复到原有效完成状态恢复原贡献；恢复不再创建第二份。撤销和恢复都检查当前任务版本与有效完成 ID。

等级 = 1 + floor(XP / 100)，当前级进度为 XP 对 100 的余数。回退可以降级。创建、生成草稿、聊天、项目全部完成和领取旧奖励不增加新版 XP。既有境界、突破、心愿、已领取奖励和 credits 保留为旧修炼历史，不能叠加到新版 XP，也不因新版回退追回旧已领取奖励。

## AI 确认与旧回执

新 AI 草稿采用任务创建契约，负责人仅限当前成员，日期可清空，说明允许为空。新只读建议最多三项，不开放创建和改状态工具。旧草稿的依赖、估时、奖励字段继续通过旧兼容入口读取，不在新界面中静默丢字段或假装已采用。

确认记录绑定 actorId、projectId、runId、规范化草稿摘要、访问代数和有效期，默认十分钟有效。执行前核对当前资格与实际参数；旧确认或 payload 内的 approved 字段不能授予权限。成员移除、重新加入、相关分工变化或修改草稿后，重新预览受影响内容。

新协作采用走服务端权威命令和回执。旧 ai_applications 本地记录继续作为旧设备历史，不伪装为全服务采用锁；登记历史回执时按来源作用域和任务映射保存，不重复创建已有输出。生成中断与写入已提交分开记录；未知结果先查回执。原子批次只呈现零项或全部提交，只有确实已生效的多个操作才存在部分完成。

## 备份恢复与实施边界

M0 只在临时生成的合成数据库运行现有 Store 和 backup API。使用 VACUUM INTO 获取包含已提交 WAL 的一致性备份；恢复时检查完整性和外键，迁移备份副本，最后切换合成目录内的指针。损坏备份和路径越界选择必须失败且保持原库与指针不变。

未来真实迁移前，应在所属账号目录使用现有备份入口，校验备份并试开副本，保留原库、旧 outbox、历史回执及迁移映射；恢复操作只选择已校验的副本。不得在数据库打开时仅复制主文件而忽略 WAL，也不删除未同步操作来绕过冲突。

M0 没有新增迁移、路由、同步协议执行器或 UI 入口。M1 负责实现本规格的共享身份与命令；M2、M3、M4 分别接入页面、XP 和 Agent。合成成员与过期确认数据是后续测试输入，不能当作共享权限已经实现的证据。
