## 重新验证

在项目根目录执行：

    powershell -NoProfile -File scripts/verify-m0.ps1

脚本运行类型检查、完整 TypeScript 测试与完整 Rust 测试，核对既有文件校验值和验收用例引用，并导出合成数据库。测试和应用的数据入口互相隔离，脚本不读取 APPDATA 中的用户数据库、不启动应用、不调用真实模型或线上服务。

每次运行在 .scratch/mvp-m0-baseline 下创建新的独立目录，保留日志、praxis.db、SQLite 一致性备份、恢复副本、全表快照和合成数据清单。不要将该目录设置为日常工作数据库。数据库文件受现有 *.db 忽略规则保护；生成器、种子和可读验证结果可随源码保留。

## 恢复验证范围

原生测试使用真实 schema 和 Store 命令建立独立任务、计划日期、确定截止时刻、树形子任务、waiting、blocked、cancelled、完成事实、待同步操作、旧已领取奖励及旧 AI 采用回执。备份恢复后逐表比较所有记录，包括迁移表的二进制校验值，检查原库没有变化。

同一测试还验证损坏备份和越界备份名称不会切换当前数据库。导出文件在连接关闭后复制；实际一致性备份使用 VACUUM INTO，不依赖复制正在写入的主数据库文件。

服务端基线使用三个真实注册的本地测试账号和现有 API，验证个人同 ID 资源、防重和身份不能被伪造。共享成员关系、撤权和确认数据仅作为 M1 至 M4 的合成规格，当前不具备生产共享效果。

## 后续接入约束

AC01 至 AC16 已给出输入、操作和预期，但产品整体用例仍待后续阶段执行。不要把参考函数或模型替身测试通过标为新界面、共享授权或真实模型验收通过。

已有文件哈希是本次基线快照。未来阶段有意修改业务代码后应保存旧清单，并创建新版本基线；不要为了让检查变绿直接覆盖原校验值。
