# AI 项目恢复与来源引用

2026-10-25（香港时间）。延续自身修炼方向，没有灵宠。本轮补齐“继续推进”的项目资料读取和采用校验，不改变奖励突破规则。

## 如何使用

1. 在项目中维护恢复卡：完成标准、当前阻塞、上次上下文、重启提示、等待说明，以及下一步和回看日期。相关推进记录可以关联项目或项目任务。
2. 打开“继续推进”，展开“本次使用资料”，核对恢复卡、近期专属记录、任务估时和安排。填写“本次可用时间”可缩小现有下一步候选；留空则不按估时筛选。
3. 生成后核对“建议引用的资料”，可展开查看实际摘录。AI 引用必须属于本次资料快照且版本匹配；有引用不等于已独立核实内容或推断正确。
4. 现有任务优先作为下一步，不重复创建。新增步骤仍先保留为可编辑草稿；明确采用后才写入，不自动改动旧任务或每日安排。修改输入或可用时间后，需要重新生成。
5. 生成后若任务、恢复卡、近期记录或相关关联发生变化，采用检查会要求重新读取并生成，保留草稿供核对，避免部分写入。

## 已实现范围

| 能力         | 本轮行为                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------- |
| 恢复资料     | 完成标准、阻塞、上次上下文、重启提示、等待说明、回看日期、明确设置或清空的下一步                  |
| 项目任务     | 最多 100 项；带真实状态、依赖、父子关系、完成标准、原因、估时、计划日期和执行日                   |
| 近期记录     | 最多 5 条最新专属记录，支持项目任务关联及历史任务关联；跨项目共享记录不会作为当前项目专属资料发送 |
| 资料预览     | 展示实际发送的项目、恢复卡、任务和记录摘录，显示资料截取提示                                      |
| 引用检查     | 最多 8 个来源，逐一校验类型、ID、版本和重复；仅展示真实存在的来源内容                             |
| 时间筛选     | 可填写 1–1440 分钟；现有候选须是可执行叶子任务、依赖已完成、未安排到未来，且估时已知并不超时      |
| 桌面一致性   | 任务、恢复卡和近期记录由单次只读事务取得；采用事务再次核对任务版本及恢复资料版本、近期记录集合    |
| 移动端一致性 | 生成时冻结本地相关资料集合，实际 SQLite 写入事务核对增删改和关联变化；缓存重试保留原始校验集合    |
| 旧版本兼容   | 保留旧请求、旧提案与旧采用命令；旧请求使用原输出结构，不强塞新增引用字段                          |

估时优先使用有效每日安排中的最新估时，再使用任务默认估时。移动端明确清空的估时保持为“未估时”，不会回退到旧同步值。时间筛选只约束现有下一步候选，新增计划仍需用户审阅；它尚不是跨项目时间分配或自动排程。

## 数据和写入边界

- 只读取当前项目范围。恢复说明最多各取 1000 个 Unicode 字符，记录标题最多 120 字符、正文最多 500 字符；任务标题、标准和原因也有摘录限制。UI 展示摘录标记。未扫描整个笔记库或外部目录。
- 生成请求 UTF-8 预算为 120000 字节；超限会明确报错，防止将超大资料直接发送给模型。
- 桌面新采用命令附带 `basisRecovery`，核对恢复卡版本及当前最近 5 条记录的 ID/版本；从“没有资料”变成“新建资料”也会失效。
- Android 的完整 `expectedAiRecoveryReadSet` 仅在本地命令及重试缓存中保留，不进入模型请求或同步实体。精简的 `basisRecovery` 是采用回执命令元数据，可随 capture 同步；不充当服务端同步事务的锁。
- 无新增迁移；数据库保持 schema 25。历史采用回执的幂等重放和撤销规则保留。
