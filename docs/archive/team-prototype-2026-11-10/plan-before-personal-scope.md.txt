# Praxis 首版分阶段开发计划

制定日期：2026-11-09  
需求基线：[首版产品需求文档](prd-mvp-v0.1.md)  
现状依据：[实现审查报告](mvp-implementation-audit-2026-11-09.md)  
执行终端：沿用现有 Windows 桌面与 Android 客户端  
任务状态：截至 2026-11-10，M0 四项及 M1-01 已完成并验证，其余 24 项待执行。完成记录见 [M0 实施与验证](m0/implementation.md)与[M1-01 实施与验证](m1/implementation-m1-01.md)。

开发采用增量改造：先建立共享项目与统一命令，再收敛核心页面，随后接入新版成长规则和 AI 协作执行，最后完成真实双账号及模型验收。保留既有个人数据、任务 ID、时间语义和高级功能的兼容访问。

## 阶段与交付目标

| 阶段 | 主要交付 | 前置依赖 | 阶段退出条件 |
| --- | --- | --- | --- |
| M0 规格与兼容 | 新旧语义映射、作用域协议、迁移样本与验收数据 | 当前 PRD 和审查报告 | 规则可执行，迁移与权限样本完整 |
| M1 共享项目与命令 | 创建者与成员、邀请、负责人、授权、共享写入与同步 | M0 | 两账号能操作同一项目任务，个人数据保持隔离 |
| M2 轻量核心体验 | 我的待办、项目列表、项目详情，行内操作和恢复反馈 | M1 的真实读写链路 | 两端手动五个核心场景可完整完成 |
| M3 成长修炼 | 新版 XP、等级、归属与回退、轻量反馈和设置 | M1 完成事实，M2 核心页面 | 任务操作与成长一致，旧奖励历史保留 |
| M4 行动 Agent | 两项能力、新草稿契约、统一确认、真实查询和可靠执行 | M1 共享服务，M2 页面 | 假模型测试下完整闭环通过，边界可核对 |

M2 是可用于体验评审的手动版本里程碑；M3 增加完整成长反馈。完整首版包含 M4 的两项 AI 能力，并须通过 M5。阶段完成按交付和验收判断，任务量需结合实际团队容量安排工期。

## 执行原则

1. 对新协作路径建立项目级授权，保留现有个人 owner 隔离，不将数据库中的 owner_id 直接解释为负责人。
2. 新查询与命令优先放入共享业务边界，客户端只负责呈现和交互。Windows Rust、移动 SQLite、API 和 Android 桥接的协议一并更新。
3. 每个任务变更、完成事实、经验归属和回执使用稳定操作标识，事务内更新相关状态。服务端为共享数据与协作结果的权威来源。
4. 新入口按阶段内部启用，未通过验收前不替换用户运行环境。高级功能转入次级入口时保留旧内容和可恢复路径。
5. 仅调整本轮需要的模块，不重写框架、不新增通用自动化编辑器、不把后续候选功能塞入当前验收。
6. 开发时基于实际工作区区分现有改动与本任务改动，提交前检查边界；不清理、回退或覆盖已有未提交工作。

## M0 规格与兼容基线

该阶段先解决共享身份、历史状态和日期、经验口径，避免 UI 与后端各自作出不同解释。

- [x] **M0-01 固化数据和验证基线。**交付隔离样本与迁移前恢复方法，涵盖个人独立任务、带子任务项目、旧截止时刻、未同步操作、已领取奖励及本地 AI 回执。保留当前测试基线记录。依赖：无。验收：样本可备份、打开和恢复，不接触真实用户库。

- [x] **M0-02 定义共享资源与命令协议。**区分登录用户、本地缓存 owner、项目创建者、任务创建人和负责人；确定项目作用域、成员、邀请、操作者、完成领取人、项目时区、命令回执与同步字段。现有不同 owner 下相同 ID 的实体不得碰撞。交付领域类型、API 和存储契约设计。依赖：M0-01。验收：同一任务被多个成员访问时只有一个业务身份，非成员默认无权访问。

- [x] **M0-03 定稿新旧规则映射。**交付日期级截止与旧瞬时时间的兼容规则、三态与 waiting/blocked/cancelled 的映射、旧树形项目与新平铺统计边界，以及新 XP 与旧修为、奖励的分离方案。建议旧层级内容保留树形兼容视图与明确的叶子统计，新建项目采用平铺口径；状态展示不能静默改写存储。依赖：M0-01、M0-02。验收：所有兼容样本都能得到明确且可解释的展示与统计结果。

- [x] **M0-04 建立首版验收数据与用例。**交付两位成员和一位非成员、一个共享项目、逾期与无日期任务、撤权与过期确认样本，覆盖 AC01 至 AC16。只复用有实际行为意义的现有测试，并为新规则添加契约与端到端场景。依赖：M0-02、M0-03。验收：每条 PRD 验收项有输入、操作和预期结果。

阶段门槛：M0 四项完成后再实施数据迁移。范围和规则产物是当前版本的补充规格，不擅自覆盖原 PRD 或旧历史需求。

## M1 共享项目与统一命令

主要位置：packages/application/src、apps/api/src/accounts.ts、entities.ts、server.ts，桌面迁移与 store，packages/storage-mobile/src，Android LanSyncPlugin.java。新增共享服务模块应保持清楚边界，不把所有规则塞入现有 server.ts 或客户端组件。

- [x] **M1-01 建立共享项目和资源授权。**增加项目创建者、成员与作用域模型，真实账号进入资源级读写检查。新项目默认只有创建者一位成员。任务增加 createdBy、assigneeId 等可信业务字段，负责人必须是当前成员。依赖：M0-02、M0-03。验收：创建者和成员可访问，非成员及伪造身份不能读取或写入；个人同步接口仍保持原隔离。

- [ ] **M1-02 实现邀请与成员变更。**提供生成、复制、撤销和重置链接，登录后主动加入；移除前预览未完成任务转交，确认后在同一授权边界完成转交和撤权。创建者自移除和所有权转移不在首版开放。依赖：M1-03。验收：AC03、AC04；撤销链接和撤权前确认不能继续产生副作用。

- [ ] **M1-03 实现统一任务命令与回执。**提供新增、编辑、单人分配、三态切换、删除及恢复；统一版本、防重、操作者、完成时负责人快照与完成时间。共享项目写入经服务端授权，返回稳定业务回执，任务变化与事件记录原子提交，为 XP 预留同事务更新接缝。依赖：M1-01、M1-05。验收：过期版本拒绝，重复请求结果一致，失败没有半条任务或错误完成事实。

- [ ] **M1-04 扩展共享同步和两端适配器。**在现有个人同步旁增加授权后的共享数据投影及增量变化，更新桌面 Rust、移动 SQLite、TypeScript 类型与 Android 桥接。维护清晰的本地保存、待同步与服务端确认状态。联网重验成员资格，清理或锁定失权缓存，拒绝撤权后排队写入；旧客户端不能通过旧接口绕过新权限或丢弃字段。依赖：M1-02、M1-03。验收：两个账号读取同一业务任务，离线恢复和冲突不产生个人数据泄露或静默覆盖。

- [ ] **M1-05 迁移旧项目与身份映射。**按 M0 的作用域协议登记历史项目，保留原任务 ID、内容与版本映射。个人任务默认负责人映射为所属账号，历史负责人未知时明确记录来源。旧项目首次共享时展示实际开放的项目与任务范围，不自动分享仅关联的私人记录。依赖：M1-01、M0-01。验收：同 ID 不同 owner 的样本不碰撞，未同步数据保留，迁移失败可恢复。

- [ ] **M1-06 验证共享业务完整链路。**覆盖成员与非成员、转交、撤权、并发编辑、操作重试、断网重连和双端缓存。回归旧账号和个人同步用例。依赖：M1-04、M1-05。验收：API、SQLite 与协议测试通过，能够用两个账号验证同一任务的身份和结果。

最小实施顺序为 M1-01 → M1-05 → M1-03 → M1-02 → M1-04 → M1-06。先打通一个项目、一项任务和一份回执，再覆盖完整操作。

## M2 轻量核心体验

主要位置：App.tsx、ProductivityView.tsx、ProjectsView.tsx、ProjectNavigation.tsx、ProjectTaskList.tsx、任务侧栏、ActionNotice.tsx、mobile/MobileApp.tsx，以及共享查询与存储投影。

- [ ] **M2-01 建立我的待办与项目统计查询。**按当前负责人和项目访问权查询全部相关任务，分逾期、今天、之后、未设日期，保留独立任务。共享计算项目完成数量、比例、逾期和读取时间，日期遵循 M0 口径。依赖：M1-06。验收：AC06、AC07；无日期或未加入每日安排的任务也能出现，转交与撤权立即影响可访问查询。

- [ ] **M2-02 收敛导航和默认首页。**主入口改为我的待办与项目，独立修炼、收件箱和其他高级视图放入次级兼容入口；保留账户与基础设置。任务与 AI 继续使用侧栏，小屏使用对应全屏面板。依赖：M0-03；正式接入依赖 M2-01。验收：三个核心页面可连续访问，旧内容仍能找到且不会重复生成任务。

- [ ] **M2-03 改造项目列表与创建流程。**增加带任务统计和逾期数的项目列表，按最近更新排序；项目创建改短弹窗，名称必填，可选展开目标与目标日期。成功直接进入详情，空项目提供添加和 AI 拆解入口。依赖：M2-01、M2-02。验收：AC01、AC06；失败保留输入，重复点击不建重复项目。

- [ ] **M2-04 完成行内任务闭环。**列表显示状态、单人负责人、可选截止日期；连续 Enter 添加，显式处理中文输入法组词；行内完成和三态切换，详情只展开说明等低频项。保留旧状态兼容标记与历史入口。依赖：M1-06、M2-03。验收：AC02、AC03、AC05；完成一次点击，字段变化在项目与个人待办一致。

- [ ] **M2-05 统一撤销、删除和保存反馈。**完成后提供 10 秒撤销，详情提供长期重开入口；删除走既有可恢复机制并提供快捷撤销。撤销检查版本，不覆盖别人后续修改。统一加载、错误、重试、输入保留和同步反馈，并触发同一组查询刷新。依赖：M2-04。验收：AC05、AC06、AC14；失败不清空输入，结果不明可核对。

- [ ] **M2-06 完成 Android 核心流程适配。**同步调整移动导航、项目列表与详情、待办分组、负责人选择、状态和任务编辑面板，使用 M1 的同一协议。依赖：M2-01 至 M2-05。验收：手机无需回桌面即可完成五个场景，包含小屏空状态、组词输入和实际保存。

阶段门槛：AC01 至 AC07、AC14、AC16 的手动路径有两端验证结果，且 AI 关闭时全部可用。

## M3 成长修炼

主要位置：cultivation-model.ts、CultivationPanel.tsx、桌面 store/cultivation.rs、新版服务端 XP 业务模块、移动端投影与基础设置。

- [ ] **M3-01 实现新版经验规则与归属账本。**每个当前有效完成任务贡献 10 XP，记录完成时负责人，完成事件重试不重复计分；重开、撤销、删除及恢复按 PRD 回退或恢复原领取人的贡献。等级按每 100 XP 自动计算。与 M1 完成命令在同一事务或可重建的可靠事件链更新，跨设备只产生一份权威结果。依赖：M1-03、M1-06、M2-01。验收：AC05、AC08；不能因重分配、重试或反复切换状态刷分。

- [ ] **M3-02 实施修炼兼容迁移。**保存旧 credits、境界、成果和已领取奖励历史，按新版有效任务生成独立 XP 投影，不叠加旧修为。执行前保留快照，说明新旧口径；历史缺少完成日期时不制造今日完成事实。依赖：M3-01、M0-03。验收：旧奖励身份和记录保留，迁移重放不增加经验，失败可以恢复。

- [ ] **M3-03 加入轻量成长 UI。**我的待办顶部展示等级、经验条和今日完成数量，完成与升级使用约 1 秒内的非阻塞反馈；增加隐藏成长、减少动效，应用于 Windows 与 Android。旧奖励功能移入兼容入口，不作为新流程必经步骤。依赖：M3-02、M2-06。验收：AC08、AC15、AC16；关闭展示仍正确记录经验。

阶段门槛：新版经验规则的完成、删除、恢复和重分配样本通过，Windows 与 Android 展示一致，旧奖励历史仍可读取。

## M4 行动 Agent

主要位置：apps/api/src/ai-contract.ts、ai.ts、新共享命令与回执模块，客户端 AiPlannerPanel.tsx、ai-planner-model.ts、ai-storage.ts，桌面与移动适配器。保留一个 Agent 和两项前台能力，不引入多 Agent 或通用编排平台。

- [ ] **M4-01 扩展契约和可信上下文。**新版本草稿增加成员负责人和可选日期，平铺任务与可选说明符合 PRD；服务端按当前用户和项目权限读取真实任务、成员及统计，个人建议使用我的待办查询。保留旧草稿和协议读取兼容，连同模型 Schema、验证器、Rust 序列化和移动适配器更新。依赖：M1-06、M2-01。验收：非法成员、伪造身份、越权资料和格式错误不能进入写入链路。

- [ ] **M4-02 精简拆解和预览交互。**默认给少量具体结果任务，展示任务、负责人、日期和可编辑说明；支持删改及一次确认。把依赖、估时、奖励、自动创建新项目等旧配置移出新核心路径，旧草稿通过兼容入口继续读取。依赖：M4-01、M2-03。验收：AC09；预览不计进度或经验，用户只需一次统一确认。

- [ ] **M4-03 建立确认与协作执行 Runtime。**保存绑定用户、项目、草稿内容与版本的确认记录，执行前重查权限和相关成员状态；通过 M1 命令批量创建，服务端持久化 run 与业务操作回执。相同任务批次跨设备采用和重试结果一致。保留原子事务，只有真实已生效部分才报告部分完成。依赖：M4-02、M1-03。验收：AC09、AC11、AC12；参数变化、撤权和重复确认均不能产生错误副作用。

- [ ] **M4-04 实现只读进度与下一步建议。**将新 resume 路径限制为读取，显示系统计算的数量和时间，建议最多三项现有任务，附理由和可打开引用；支持项目与个人待办两处入口。新只读路径不开放创建、改状态或改日期工具。依赖：M4-01、M2-01。验收：AC10；任何回答和工具结果都不能触发任务写入，统计与数据源一致。

- [ ] **M4-05 完善运行状态、停止和恢复。**保存读取、整理、待确认、执行、终态与未完成事项；保留用户输入和稳定操作标识。生成失败可重试，写入结果不明先查回执；停止后报告已提交内容。将预算按 PRD 默认值统一为最多 6 轮、60 秒主动执行，安全重试最多一次；等待确认不消耗执行预算。依赖：M4-03、M4-04。验收：AC11、AC12、AC13；刷新、服务重启、超时和取消都有明确结果。

- [ ] **M4-06 验证 Agent 两端完整闭环。**使用受控模型替身覆盖拆解、成员日期编辑、一次确认、重复采用、服务重启、权限变化、数据过期、只读建议和服务关闭，回归旧 AI 草稿恢复与回执读取。依赖：M4-05、M3-03。验收：Windows 与 Android 接口行为一致，旧协议仍可读；记录尚未完成的真实模型验收，留到 M5-03。

阶段门槛：假模型下能核对每次动作和实际任务结果。现有 API 生成记录不能单独证明协作写入已成功。

## M5 整体验收与交付

- [ ] **M5-01 执行自动化回归。**运行现有 typecheck、test、test:native，补新权限、成员、日期、XP、AI Runtime 与兼容迁移测试；运行根 build 和 API build 确认产物可构建。依赖：M2、M3、M4。验收：无当前范围失败，原有数据安全与兼容用例通过，失败项有明确修复结果。

- [ ] **M5-02 完成两端真实界面与协作验收。**在隔离环境使用真实 Windows 和 Android 客户端、两个成员账号及非成员，逐条执行 AC01 至 AC16 的手动部分与整体验收旅程，检查键盘、中文输入法、小屏、断网、关闭重启、撤权和缓存边界。依赖：M5-01。验收：记录客户端版本、步骤、截图和实际数据结果，单元测试不能替代界面结论。

- [ ] **M5-03 完成真实模型和服务异常验收。**在已配置且允许测试的模型服务验证两项能力、生成质量、任务引用、日期建议及关闭和超时表现；不把模型替身结果标为真实生成通过。依赖：M5-01、M4-06。验收：拆解与只读建议均有真实响应及最终业务结果；配置或网络未具备时，保留该项未完成，产品标记为对应内测范围。

子任务与依赖的新能力、甘特和看板扩展、工时与工作量预测、自动排程、复杂角色和审批、聊天评论附件、商城货币宠物、长期记忆、RAG、Wiki、多 Agent 和外部自动执行均不进入当前任务清单。
