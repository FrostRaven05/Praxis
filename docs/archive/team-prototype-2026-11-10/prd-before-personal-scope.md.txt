# Praxis 首版产品需求文档

版本：v0.1  
日期：2026-11-09  
定位：任务与项目管理聚焦版  
适用读者：产品、设计、开发与测试  
状态：需求基线，功能交付以验收结果为准

Praxis 帮助个人与小型团队把目标拆成可执行任务，明确负责人，并持续看见进展。首版围绕创建项目、拆解与分配任务、更新任务状态、跟踪项目进度、查看个人待办五个核心场景。成长修炼提供个人行动反馈，AI 减少拆解和整理工作，两者都不增加手动管理的必经步骤。

## 产品目标与设计原则

首版优先解决三个问题：项目开始时不知道如何拆解；协作时不清楚谁负责、做到哪里；同时推进多个项目时找不到自己的下一步。

目标用户为个人及约 2 至 10 人的小型协作团队。团队规模是产品设计假设，用于约束复杂度。首版不承担组织级项目组合、资源调度或绩效管理。

核心闭环为：

创建项目 → 拆解任务 → 明确负责人 → 查看个人待办 → 更新状态 → 同步项目进度与个人成长。

| 设计原则 | 产品要求 |
| --- | --- |
| 快速开始 | 项目仅名称必填；任务仅标题需要用户输入，其余使用默认值 |
| 责任明确 | 每项任务只有一位负责人，默认为任务创建者 |
| 就地操作 | 添加、分配和状态切换在任务列表完成，补充内容再打开侧栏 |
| 数据一致 | 项目、个人待办、AI 查询引用同一条任务 |
| 反馈可信 | 保存结果、任务进度和经验来自实际业务记录 |
| AI 可选 | 不使用 AI 时，五个核心场景仍能完整完成 |
| 游戏化轻量 | 成长信息放在已有页面，不增加打卡、领奖或养成的必经步骤 |

## 版本边界与既有项目关系

本文件定义本次讨论形成的轻量版本范围，独立保存为产品评审和后续开发拆解的依据。仓库中的 Spec.md、Praxis_SPEC_v0.1.md 和 Praxis_DEV_PLAN_v0.1.md 包含更广的个人工作台与双端需求；本次聚焦版本涉及的取舍以本文件为准，其余能力保留为既有规格和实现背景。

已有功能不因列入本文件的后续范围而被删除；实施时复用现有账号、持久化、同步和设计系统。调整入口或数据结构时保留用户内容与已有含义。本文件不代表相关功能已经实现或通过验收。

| 范围 | 首版必须包含 | 后续迭代方向 |
| --- | --- | --- |
| 项目 | 名称、可选目标与目标日期、成员协作、任务列表 | 项目模板、归档管理、里程碑、项目组合 |
| 任务 | 平铺任务、单人负责、三种状态、可选截止日期与说明 | 子任务、依赖、优先级体系、标签、重复任务 |
| 进度 | 任务完成数量与比例、逾期数量 | 甘特图、看板、工时、工作量预测、跨项目报表 |
| 个人待办 | 跨项目汇总、按日期组织、直接更新状态 | 自定义视图、自动排程、日历整合 |
| 协作 | 真实账号、项目邀请、创建者与成员两类身份 | 角色矩阵、审批流、访客、实时共同编辑 |
| 成长 | 个人经验、等级、完成反馈 | 技能树、团队挑战、成就体系、心愿奖励扩展 |
| AI | 任务拆解草稿、进度与下一步建议 | 长期记忆、RAG、动态重排、多 Agent、外部自动执行 |
| 协作内容 | 任务内纯文本补充说明 | 评论、附件、聊天、外部消息通知 |

已有独立任务继续保留，并在分配给自己时进入个人待办；本次五个核心场景不要求新增收件箱、习惯或记录模块。已存在的计划日期与真实截止日期继续分别保存。新建轻量任务仅暴露截止日期，不能把旧计划日期直接转换成截止日期。

任务完成比例只描述任务数量。已有项目成果、验收标准和生命周期继续保留其语义，不由任务全部完成自动改写。

## 用户与协作规则

用户登录后可以独自管理项目，邀请成员是可选步骤。沿用现有账号入口，不在核心流程前增加团队初始化向导。

| 身份 | 首版权限 |
| --- | --- |
| 项目创建者 | 管理项目基本信息、邀请与移除成员、管理项目任务 |
| 项目成员 | 查看项目及任务，创建、编辑、分配和更新项目内任务 |
| 非项目成员 | 无权查看项目数据，持有有效邀请链接时可申请加入 |

每个项目有一位创建者。负责人必须是当前项目成员，不设置多负责人、自定义角色或权限配置页。协作操作记录实际操作者。

邀请链接由创建者生成，可复制、撤销或重置。新用户登录后看到项目名称并主动加入，系统才开放项目数据。任务不能分配给尚未加入的账号，成员选择器提供“邀请成员”入口。

移除成员时，系统展示该成员负责的未完成任务，默认将其转交创建者，统一确认后执行。已完成任务保留原负责人历史。移除生效后立即取消其项目访问权限；离线缓存遵守既有账号与缓存隔离规则。

## 页面结构

首版保留两个主导航入口，承载三个核心页面。成长与 AI 使用局部组件，账户与基础设置位于次级菜单。

    Praxis
    ├─ 我的待办 默认首页
    │  ├─ 个人等级与经验条
    │  ├─ 未完成任务
    │  ├─ 已完成任务 折叠区
    │  └─ 下一步建议
    ├─ 项目
    │  ├─ 项目列表
    │  └─ 项目详情
    │     ├─ 项目名称与可选目标
    │     ├─ 任务完成比例与逾期数量
    │     ├─ 成员入口
    │     ├─ 任务列表与行内添加
    │     └─ AI 拆解入口
    └─ 账户与基础设置 次级入口

任务详情使用侧栏；小屏可切换为同内容的全屏面板。创建项目使用短弹窗。AI 使用侧边面板，小屏为全屏面板，不新增独立聊天首页。

### 我的待办

页面首先展示分配给当前用户的未完成任务，包含全部可访问项目，不要求用户先把任务手动加入今天。

任务自动分为“逾期、今天、之后、未设日期”，空分组不展示。组内按截止日期升序，同日期按创建时间排序；无日期按创建时间排序。每条任务显示标题、状态、项目名称及可选截止日期。

已完成任务默认折叠，可展开查看和重开。点击标题打开详情，点击项目名称进入项目。顶部成长条保持紧凑，任务列表是页面主体。

### 项目列表

每个项目显示名称、任务完成数量与比例、逾期数量。新项目显示“还没有任务”。列表按最近更新排序，首版不增加分组管理或多种视图。

创建按钮始终可见。没有项目时，只提供“创建第一个项目”的主操作和简短说明。

### 项目详情

首屏依次为项目名称与可选目标、进度摘要、成员入口、任务列表。项目目标与日期可以后补，不以完整填写作为添加任务的前提。

任务行显示标题、状态、负责人和可选截止日期。默认显示未完成任务，已完成任务在底部折叠。底部输入框支持连续添加，按 Enter 保存后继续输入。中文输入法组词中的 Enter 不触发保存。

任务详情仅补充说明、截止日期等低频编辑，不重复构建第二套任务状态。

## 核心用户流程

### 创建项目

| 阶段 | 用户操作 | 系统反馈 |
| --- | --- | --- |
| 进入 | 在项目列表点击“创建项目” | 打开短弹窗，光标定位到名称 |
| 填写 | 输入项目名称，可选展开目标与日期 | 显示必要的字段校验，不要求其他配置 |
| 保存 | 点击“创建” | 保存成功后直接进入项目详情 |
| 开始行动 | 点击“添加第一项任务”或“AI 帮我拆解” | 就地进入对应流程 |

项目名称去除首尾空白后不能为空。保存中防止重复提交；失败保留输入，不跳转空项目。个人使用时自动将自己设为创建者和首位成员。

### 拆解与分配任务

手动路径：打开项目 → 输入任务标题 → Enter 保存 → 继续输入下一项。负责人默认自己，状态默认待办，日期为空。

分配路径：点击负责人 → 选择项目成员 → 保存。需要邀请时，创建者先复制邀请链接，成员加入后再进行分配，不要求为了分配任务进入管理后台。

| 情况 | 系统反馈 |
| --- | --- |
| 保存成功 | 新任务出现在项目列表，并进入负责人的个人待办 |
| 负责人变更 | 两位成员的待办归属同步调整，其他任务信息不变 |
| 成员已退出或被移除 | 拒绝分配，保留其他编辑内容，提示重新选择 |
| 网络尚未同步 | 明确显示待同步，不把本地保存表示为对方已经收到 |
| 添加失败 | 保留标题和已填字段，提供重试 |

“拆解”首版以平铺列表完成。AI 路径在 AI Agent 设计中定义。

### 更新任务状态

任务固定使用“待办、进行中、已完成”。创建后为待办；用户可直接切换状态，不强制经过进行中才能完成。

点击完成控件即可完成，无需打开详情。已完成任务可重开为待办或进行中。状态保存后，个人待办、项目进度和成长信息同步刷新。

完成后提供短提示和 10 秒“撤销”入口。撤销使用任务版本校验；若任务已被其他成员修改，展示当前情况并让用户选择重开，避免覆盖后续编辑。任务详情始终保留重开入口，不依赖短提示。

删除任务放在详情的次级菜单，使用可恢复删除并提供撤销。删除时同步更新统计与经验；首版不增加独立回收站页面。

### 跟踪项目进度

用户在项目列表快速查看，在详情通过实际任务判断情况，不要求额外填报进度。

| 指标 | 计算规则 |
| --- | --- |
| 任务完成数量 | 当前未删除任务中，状态为已完成的数量 |
| 任务总数 | 当前项目内全部未删除任务，包括三种状态 |
| 任务完成比例 | 已完成数量 ÷ 总数，以整数百分比显示 |
| 逾期数量 | 未完成且已超过截止日期的任务数 |
| 无任务 | 显示“添加任务后开始跟踪进度”，不显示 0/0 或 0% |
| 全部完成 | 显示“全部任务已完成”，给予轻量反馈 |
| 新增或重开任务 | 重新计算比例，恢复显示当前任务进度 |

目标日期用于表达项目期望；任务截止日期用于个人待办排序和逾期判断，二者不自动相互覆盖。轻量任务使用日期级截止日期，按项目时区当天结束为边界；项目时区默认取创建者账户时区，不新增初始化配置。跨时区查看时，在必要位置标明项目时区。

全部任务完成后不自动归档或声明项目成果验收通过。项目详情仍可继续添加、修改任务。

### 查看个人待办

用户打开应用 → 看到自己的未完成任务 → 按日期选择下一项 → 行内切换进行中或完成 → 进度与成长同步更新。

没有待办时显示“当前没有待办”，提供“查看项目”入口；用户没有项目时提供“创建项目”。个人待办只展示当前有权访问的数据，退出项目后不继续暴露项目内容。

### 使用 AI 拆解项目

用户在项目详情点击“帮我拆任务” → 输入目标和限制 → Agent 读取现有任务与成员 → 生成可编辑草稿 → 用户调整并统一确认 → 执行创建 → 核对实际结果 → 刷新项目和个人待办。

没有日期、成员分工等非关键资料时，先提供可修改建议。只有缺失信息会明显改变任务范围或交付结果时才追问。AI 不通过反复访谈阻塞简单项目。

## 成长修炼与游戏化

### 价值与展示

成长修炼用于让用户感知持续行动。个人经验只对自己展示，不作为团队排名或绩效依据，不对用户作人格、能力或自律程度评价。

“我的待办”顶部显示等级、当前级经验和今天完成数量。例如：

    Lv.3  持续行动者
    60 / 100 XP
    今天已完成 3 项任务

称号为装饰文案，不解锁任务管理能力。首版不增加独立修炼页面、领取奖励步骤或强制每日目标。

### 经验与等级规则

有效经验总值记为 XP。每项当前有效的已完成任务贡献 10 XP，每累计 100 XP 升一级。等级为 1 加上 XP 除以 100 的整数部分，当前级进度为 XP 除以 100 的余数。

| 事件 | 经验处理 |
| --- | --- |
| 首次完成任务 | 给完成时的负责人记入 10 XP，并保存领取人 |
| 相同完成事件重复到达 | 不重复记分 |
| 撤销完成或重开任务 | 撤回该任务给原领取人的 10 XP |
| 重开后再次完成 | 按当时负责人重新计入一份有效经验 |
| 删除已完成任务 | 撤回该任务的经验；恢复时按保存记录恢复一份 |
| 修改已完成任务负责人 | 历史经验不转移；重开并再次完成时使用新负责人 |
| AI 生成建议、创建任务或聊天 | 不产生经验 |
| 项目全部任务完成 | 仅给予完成反馈，不额外奖励项目经验 |

同一任务同时最多贡献一份有效经验，净值不会随状态反复切换而累加。经验因撤销或删除回退时等级可以同步回退，界面说明“经验已随任务状态更新”。

“今天完成数量”按实际完成时间与查看者账户日期计算，统计当前有效且奖励归属于自己的任务。项目和个人待办共同引用完成记录，避免跨页面重复计数。

### 视觉与动效

默认采用轻 RPG 任务日志风格，沿用 DESIGN.md 的基础组件与明暗主题。使用紧凑面板、等级徽章、经验条和轻量向导形象表达游戏感；成长色可使用现有紫色主题色，状态颜色沿用已有成功、警告和错误语义。

项目、负责人、状态、截止日期保留通用名称。任务列表占据主要空间，装饰元素不替代信息。

完成与升级反馈不使用阻塞弹窗，动效控制在约 1 秒内。基础设置提供“减少动效”和“隐藏成长信息”，关闭后仍正常记录任务与经验。状态同时使用文字或图标表达，键盘操作可见焦点，小屏主要操作易于触达。

不纳入首版：连续打卡惩罚、排行榜、商城、货币、装备、宠物、地图和任务管理能力解锁。

## AI Agent 设计

### 定位与能力边界

界面名称为“行动助手”，游戏化呈现可称“同行向导”。首版只有一个 Agent，共用同一套业务权限与上下文，不要求用户选择模型、框架、角色或自动化流程。

Agent 完成任务管理中的整理和创建动作。实际业务任务的交付由成员完成并确认，Agent 不根据聊天内容自行宣布任务完成。

| 能力 | 读取内容 | 输出 | 写入规则 |
| --- | --- | --- | --- |
| 目标拆成任务 | 当前目标与限制、项目说明、已有任务、当前成员 | 少量可执行任务、可选负责人和日期建议 | 用户检查草稿并统一确认后批量创建 |
| 进展与下一步 | 项目实时统计或自己的待办、状态、日期、相关说明 | 进展摘要和最多三条行动建议 | 只读，不自动修改状态、负责人或日期 |

项目摘要区分系统事实与行动建议。完成比例、数量和日期由业务系统计算；建议显示任务链接和理由，例如“明天截止，当前仍为待办”，并标明数据读取时间。没有充分信息时说明依据，不生成虚构阻塞、依赖或工作量结论。

### 任务草稿规范

草稿默认给出约 3 至 7 项任务，按目标规模调整，不以凑数量为目的。任务标题表达具体交付结果，例如“完成报名页并可提交数据”；说明中给出简短完成标准。

首版输出平铺任务。需要先后顺序时在草稿中说明，不创建依赖图或多层子任务。优先检查已有任务，发现可能重复时让用户选择保留或跳过，不自动合并或删除。

负责人只能选择当前成员。日期属于建议，统一显示在预览中；用户可以清空。未明确的信息不能伪装成已经商定的承诺。

预览卡支持修改标题、负责人、日期和说明，删除草稿项，并以一次“创建这些任务”完成确认。草稿不会提前计入个人待办、项目统计或经验。

### 系统职责划分

以下机制属于系统内部实现，不增加面向用户的配置项。

| 组件 | 首版职责 |
| --- | --- |
| Prompt | 规定角色、输出约束、材料使用方式和能力边界 |
| Context | 按本次请求选择必要的目标、限制、任务、成员与真实结果 |
| 业务工具 | 查询项目上下文、查询个人待办、查询系统统计、批量创建任务 |
| Tool Runtime | 校验参数、当前身份、项目权限、成员关系及确认内容，受控执行并保存结果 |
| Agent Loop | 必要时补充读取，根据真实结果继续或结束；简单查询使用固定流程 |
| State 与 Working Memory | 保存目标、限制、草稿、待确认变更、执行结果及剩余事项 |
| Harness | 将上述组件与预算、停止、恢复和结果核对机制装配起来 |

工具复用正常业务服务，不给模型直接数据库写入、任意脚本或外部消息发送能力。当前用户和权限来自登录态；模型参数不能授予权限或表示已经获得确认。项目说明、任务正文等作为业务资料处理，其中的文字不能改变系统执行规则。

### 确认策略

查询、统计和生成建议在用户权限内直接执行。AI 生成的任务和分配方案在同一张预览卡统一确认，执行时不再逐项弹窗。

确认记录绑定当前用户、项目、具体任务草稿与参数。预览后用户修改方案，使用修改后的内容确认；确认后如果涉及的成员资格、权限或相关业务状态发生变化，先说明差异，重新确认受影响部分。

执行前再次检查权限和有效性，确认记录不替代权限。首版不开放 AI 删除任务、修改已有任务状态、自动邀请成员或向外部发送消息。

### 运行状态与中断恢复

用户可见状态为：

读取资料 → 整理方案 → 等待确认 → 执行中 → 已完成。

异常终态包括部分完成、失败和已停止。等待确认时可修改或取消草稿。读取与生成阶段支持停止；执行阶段停止后先核对已经生效的动作，再报告结果。

每次运行保存运行标识、用户与项目、目标和限制、草稿版本、确认内容、业务操作标识、实际创建的任务 ID 和未完成事项。聊天历史不能替代这些业务记录。

| 情况 | 系统处理与用户反馈 |
| --- | --- |
| 模型生成失败 | 保留输入，允许重试或手动添加 |
| 查询或网络暂时失败 | 有限重试，失败后说明原因并保留草稿 |
| 部分任务创建成功 | 列出成功与失败项，仅对未完成项重试 |
| 写入结果不明 | 先按业务操作标识查询实际结果，不盲目重复写入 |
| 刷新页面或重新进入 | 找回待确认草稿或运行结果，核对后继续未完成部分 |
| 成员被移除或权限撤回 | 停止相关动作，说明原因，保留用户仍有权查看的内容 |
| 用户停止 | 明确已生效操作；停止不自动回滚已创建任务 |

批量创建使用稳定的业务防重标识；相同请求重试或重复点击只能产生同一批有效任务。工具调用 ID 不单独承担业务防重。

内部默认最多 6 轮模型调用、60 秒主动执行时间，等待用户确认不占执行预算。仅对明确可重试且具备防重保证的操作最多自动重试一次。达到上限时保留结果并结束等待，内部预算可根据实际评估调整，不暴露复杂配置页。

### AI 不可用与首版交付

关闭 AI、离线或服务不可用时，手动项目与任务管理继续可用。入口明确显示当前状态，不让用户进入无法完成的空白对话。

完整首版验收包含两项 AI 能力。提供方未接入时可以交付标注清楚的手动内测版本，但不能据此将 AI 能力标记为已交付。首版不设置独立长期记忆、向量数据库、RAG、Wiki 或多 Agent 编排。

## 保存与同步反馈

沿用现有持久化与同步机制，区别显示“本地已保存、待同步、已同步、失败”。本地状态更新成功后即时刷新当前视图，远端确认后再表示已经同步。

可离线保存的编辑进入既有同步队列。依赖服务器确认的成员加入、权限变化和 AI 写入使用明确的在线状态，不制造协作已经生效的假象。

并发修改遵循既有版本与冲突规则；无法安全合并时保留用户输入并说明冲突。普通任务操作与 AI 使用同一套业务校验，避免出现 AI 能越过手动操作限制的情况。

## 首版验收标准

以下为产品验收要求，不表示当前工程已通过。测试使用隔离账号和数据；涉及协作的用例必须验证两个真实账号的权限与数据结果。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC01 | 新用户创建项目 | 只输入名称即可成功，进入详情并能添加第一项任务 |
| AC02 | 连续添加任务 | 按 Enter 连续添加，默认值正确，中文组词不误提交 |
| AC03 | 邀请与分配 | 第二账号加入后可被分配，任务进入其待办；非成员无法读取 |
| AC04 | 成员移除 | 未完成任务转交结果明确，原成员失去访问，旧确认无法继续越权执行 |
| AC05 | 更新与撤销 | 两处视图、项目统计与经验一致，撤销不覆盖其他成员的新修改 |
| AC06 | 进度边界 | 空项目、全部完成、新增、重开、删除与恢复的数量和比例正确 |
| AC07 | 日期与待办 | 无日期、今天、之后和逾期分组正确，目标日期不覆盖任务截止日期 |
| AC08 | 成长去重 | 完成、重开、再次完成、重复请求、删除和恢复均最多保留一份有效经验 |
| AC09 | AI 拆解 | 草稿可修改；未确认不写入；确认后创建结果与预览一致 |
| AC10 | AI 建议 | 数字与实时查询一致，建议能打开对应任务，最多三条 |
| AC11 | AI 中断 | 重复点击、超时、刷新与结果不明不产生重复任务，成功和失败项可核对 |
| AC12 | AI 停止与权限 | 停止后准确报告已生效动作，权限变化时停止相关写入 |
| AC13 | AI 不可用 | 手动五个核心场景全部可完成，入口状态明确 |
| AC14 | 保存与同步 | 重启可恢复已保存内容，待同步与远端成功可区分，失败不丢输入 |
| AC15 | 游戏化体验 | 完成与升级不阻塞操作，减少动效和隐藏成长后可正常工作 |
| AC16 | 小屏与空状态 | 三个页面可完成核心操作，无空按钮、装饰遮挡或虚假示例数据 |

整体验收至少包含一次完整旅程：创建项目 → 手动或 AI 拆解 → 邀请并分配 → 第二账号查看待办 → 更新状态 → 创建者查看进度 → 全部任务完成 → 重开一项 → 进度和经验正确回退。

产品体验验收同时检查：创建项目仅一个必填字段；行内新增任务仅输入标题；完成任务一次点击；AI 草稿一次统一确认；成长系统无领取步骤。

## 产品验证指标

首轮使用测试围绕真实项目记录以下指标，先收集基线再设定改进目标，不把任务数量和经验当作生产力评价。

| 指标 | 记录口径 | 用途 |
| --- | --- | --- |
| 首次形成行动的时间 | 开始创建项目至第一项真实任务保存 | 检查创建与拆解成本 |
| 找到下一步的成功情况 | 用户能否在首页指出准备执行的任务及原因 | 检查待办组织与建议价值 |
| 状态更新成本 | 完成一项任务的操作次数及是否打开详情 | 检查高频操作是否简洁 |
| AI 草稿采纳情况 | 确认创建比例、删改情况与后续实际执行反馈 | 检查拆解是否有用 |
| 数据与恢复问题 | 保存失败、重复创建、权限错误和丢输入的发生情况 | 检查可靠性 |

## 后续迭代方向

后续能力仅记录方向，不进入首版验收或默认工期。

| 方向 | 候选能力 | 启动依据 |
| --- | --- | --- |
| 更复杂项目 | 子任务、依赖、里程碑、看板、甘特图 | 平铺任务已无法表达真实工作关系 |
| 更高效个人安排 | 优先级、标签、重复、日历与自动排程 | 用户持续出现排序或安排困难 |
| 更深入协作 | 评论、附件、通知、访客与细分权限 | 团队沟通和成员范围有明确需求 |
| 更丰富成长 | 成就、技能树、可选挑战、已有奖励机制整合 | 基础成长被持续使用，且不挤占任务主体 |
| 更强 AI 上下文 | 项目长期记忆、资料检索、RAG | 当前项目数据已不足以支持可靠建议 |
| 更强 AI 执行 | 自然语言更新任务、动态重排、多 Agent、外部工具 | 两项基础能力稳定，并有可核对的授权和执行结果 |
