# T19 — 未来重复规则与例外

2026-10-09，Windows 本地实现；对应 REPEAT-003/004、TIME-005 与 AT-22 的本地部分。同步与 Android 验收不在本次范围。

重复任务页面新增“修改未来规则”，指定明天或之后的生效日期、标题、间隔或星期和规则时区。确认前逐项列出已生成的未来任务：保留完成历史、保留手动例外、恢复原定日期并更新标题，或取消不再匹配的新规则发生项。默认保留手动修改，覆盖例外需要单独勾选确认。未来已预约规则被替换的影响在表单明确说明。缺少的新发生日期在之后的显式补齐命令生成。

单次任务编辑仍在详情完成。改期保留 task ID、模板 ID 和 occurrence_key。规则编辑不修改生效日前任务、已完成任务或软删除任务；不在新规则中的未来任务保留原身份并取消，不物理删除。停止模板仍保留已生成历史和未来任务，项目删除复用 T15 停止模板流程。

迁移 0017 新增 recurrence_rules，保存生效日和独立的日历锚点；工作空间时区迁移不会重置每隔 N 天的周期。Zone 命令接收 expectedTemplates，启用模板集合/版本不一致时整个事务拒绝。工作空间时区确认会同时更新启用模板及明日起所有规则版本的时区，已有任务日期、发生身份与习惯记录不变。首版重复项全为日期型，没有小时级未来时刻。

Edit 命令要求模板版本和预览任务完整 ID/版本集合匹配；规则、任务、审计、outbox 同事务。查询不产生写入。重复规则和所有例外随 SQLite 备份自动覆盖。

验证：pnpm typecheck 通过；公开 Store seam 的 recurrence 集成测试 6 组通过，包括未来生效历史保持、陈旧预览拒绝、例外保留/确认覆盖、时区预览强制和间隔锚点不漂移，以及原有分批、唯一身份、停止/项目终结测试。桌面 UI 和最终完整测试、双轴代码审查由主任务统一执行。未声称真机或同步验收通过。

## 审查修正与领域边界

规则编辑现在保留仍匹配发生项原有的进行中、阻塞与等待状态；只有原先已取消且用户允许覆盖时才恢复待办。不再以修改标题/日历规则隐式重置执行进度。编辑器重新打开时读取 recurrence_rules 最新已预约版本；改变生效日期时载入该日期适用规则，避免回显模板建立时的旧值。

`Store::recurrence_edit_preview(&RecurrenceAction)` 为纯读预览，和事务执行共享 `edit_status` / 规则验证逻辑。客户端只呈现服务端逐项效果并保存该次预览的完整命令（包括模板/任务版本），后续页面刷新不会偷偷替换已确认预览的版本。Rust 持久化领域规则是重复日历、未来例外与写入约束的权威；TypeScript 仍负责既有只读汇总/排版与输入交互，不复制重复规则算法。本地桌面双栈兼容的调整不迁移旧业务对象，也不表示新增手机/服务端领域实现；后续同步仍需复用规范并用跨语言向量验证。这补充 TECHNOLOGY 与 P0 兼容决策，避免将旧架构的共享 TypeScript 规则目标误称为当前所有原生写入已经共享实现。

定向 recurrence 集成测试现为 7 组通过。新增公开 Store seam 验证预览不写数据，以及预览/执行对进行中、阻塞、等待的状态保持；类型检查通过。

追加复查修正：进行中、阻塞和等待的发生项也作为手动例外。未勾选覆盖时，即使新频率不再匹配，该实例整条保留（标题、日期、执行状态、版本均不变）；明确覆盖时，不匹配的实例取消，匹配的实例保留原执行状态。回归覆盖三种执行状态各自匹配/不匹配、默认保护/明确覆盖的分支，且预览效果与提交一致。先观察新增断言失败（cancel ≠ preserveOverride），再修复服务端例外判定。
